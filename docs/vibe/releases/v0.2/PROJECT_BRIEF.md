# Phase 01：终端对话 PRD

> 优先级：P0
> 状态：已交付（2026-08-26）
> 前置阶段：Phase 00
> 对应里程碑：M0 可运行基础

## 1. 阶段目标

提供稳定的终端模型对话能力，完成“配置模型—输入消息—流式查看回答—继续对话—安全退出”的最小体验。本期只建设聊天基础，不允许模型调用本地工具。

## 2. 用户价值

- 用户可以在项目目录中直接与模型持续对话。
- 用户能看到首个输出的实时反馈，而不是等待完整响应。
- 模型配置和错误均以可诊断方式呈现，为后续 Agent 循环提供可靠基础。

## 3. 用户故事

- 作为新用户，我希望通过环境变量配置一个模型并开始对话。
- 作为开发者，我希望回答以流式方式显示，并能使用 Ctrl+C 中断当前响应。
- 作为排障用户，我希望鉴权、限流、网络和配置错误得到不同提示。

## 4. 本期范围

- 单一默认 Provider 的文本模型接入。
- OpenAI-compatible Chat Completions 风格的基础消息和流式响应。
- 会话内多轮消息历史。
- `/help`、`/clear`、`/config`、`/exit` 基础命令。
- API Key、模型名、Base URL、超时和日志级别配置。
- 请求取消、超时、重试边界和错误分类。
- Token 使用量在 Provider 返回时展示；缺失时明确标记未知。

## 5. 核心流程

```text
启动 XhlCLI
  → 检查项目与模型配置
  → 显示当前模型和输入提示
  → 用户输入问题
  → 发送消息历史
  → 流式展示回答
  → 保存本次会话内历史
  → 等待下一次输入
```

## 6. 功能需求

### FR-01-01 配置加载

配置按“命令行参数 > 环境变量 > 本地配置文件 > 默认值”合并。启动时展示 Provider 和模型名，但不得显示 API Key。

### FR-01-02 流式对话

模型文本到达后应增量输出。首个文本片段出现前显示非阻塞等待状态；响应完成后恢复输入提示。

### FR-01-03 多轮历史

当前进程内保留 `system/user/assistant` 消息顺序。`/clear` 清除当前对话但不删除用户配置。

### FR-01-04 中断与退出

响应生成期间第一次 Ctrl+C 取消当前请求并回到输入；空闲状态下退出需走统一清理流程。不得因取消留下无法继续输入的终端状态。

### FR-01-05 错误分类

至少区分缺少配置、鉴权失败、请求限流、网络不可达、服务端错误、响应格式错误、超时和用户取消。用户提示包含可执行的处理建议。

### FR-01-06 日志与脱敏

普通模式只展示必要错误；调试模式可以记录请求元数据和事件，但必须脱敏 Authorization、API Key 和可能的凭据参数。

### FR-01-07 基础命令

- `/help`：显示命令说明。
- `/config`：显示当前非敏感配置及配置来源。
- `/clear`：清空会话历史并给出确认。
- `/exit`：安全退出。

## 7. 非目标

- 不提供工具调用、文件修改和命令执行。
- 不提供多 Provider 运行时切换。
- 不持久化完整会话历史。
- 不实现 Markdown 复杂渲染或全屏 TUI。
- 不展示或保存模型私有思维过程。

## 8. 异常与边界场景

- 用户提交空白输入时不发送请求。
- 响应中途断流时保留已经显示的文本，并标记响应未完整结束。
- 模型返回未知事件类型时记录调试信息并安全忽略，不能导致会话崩溃。
- 历史包含非法消息顺序时拒绝发送并提示内部一致性错误。
- Base URL 非法时在首个网络请求前失败。

## 9. 非功能要求

- 首个流式片段到达后 100 毫秒内显示。
- 所有 HTTP 调用具备连接、读取和整体请求超时。
- 模型客户端可用测试替身替换，CLI 测试不依赖真实 API。
- macOS 基础输入和 Ctrl+C 行为有验证记录；本期不承诺 Windows/Linux 兼容性。

## 10. 验收标准

1. 配置有效时可以连续完成至少 5 轮流式对话。
2. `/clear` 后下一次请求不携带清理前的用户和助手消息。
3. 响应中按 Ctrl+C 可以取消请求并继续输入。
4. 缺少 Key、错误 Key、超时和 429 均显示不同错误与建议。
5. 调试日志和终端输出中不出现完整 API Key。
6. 模拟流式、断流、超时和取消的自动测试通过。

## 11. 测试与验证

- 单元测试：配置优先级、消息序列、SSE 事件解析、错误映射、脱敏。
- 集成测试：Mock HTTP Server 返回正常流、错误码、延迟和中断流。
- 手工验证：真实 Provider 完成多轮问答与 Ctrl+C 取消。
- 回归检查：`--help`、`--version` 仍保持 Phase 00 行为。

## 12. GitHub 交付物

- Provider 配置示例和最小对话示例。
- 流式响应演示 GIF。
- Mock Server 集成测试。
- Phase 01 Release Notes，明确“本期不具备本地工具权限”。

## 13. 下一阶段接口

本期必须稳定输出模型消息、流式事件、取消信号和错误类型，Phase 02 将在此基础上增加工具描述、工具调用消息和 Observation 回灌。

## 14. 变更记录

| 版本 | 日期 | 变更 |
|---|---|---|
| v1.0 | 2026-08-25 | 建立终端对话范围与验收标准 |
| v1.1 | 2026-08-26 | 完成实现、50 项离线测试与本地 JAR 验证；真实 Provider、三平台 CI 和演示验收待完成 |
| v1.2 | 2026-08-26 | 完成真实 Provider 五轮会话、Ctrl+C 恢复、脱敏演示和 macOS CI 验收，Phase 01 正式交付 |

# Phase 02：ReAct Agent PRD

> 优先级：P0
> 状态：已交付（2026-08-27）
> 前置阶段：Phase 01
> 对应里程碑：M1 可用 Coding Agent

## 1. 阶段目标

在稳定模型对话之上建立 ReAct Agent 执行循环，使模型能够根据任务状态选择结构化工具、接收执行结果并继续决策，直到给出最终答复或触发停止条件。本期使用受控的演示工具验证循环，不开放真实文件写入和命令执行。

## 2. 用户价值

- 用户不再需要手工拆分“先查什么、再做什么”，Agent 可以根据 Observation 自主推进。
- 每一步工具调用和结果都可观察，失败后可以继续调整策略。
- 循环受到次数、时间、取消和重复调用限制，不会无限运行。

## 3. 用户故事

- 作为用户，我希望模型在需要信息时主动调用工具，而不是编造结果。
- 作为用户，我希望知道 Agent 当前调用了哪个工具以及调用是否成功。
- 作为维护者，我希望 Agent 循环可用假的模型与工具进行确定性测试。

## 4. 本期范围

- ReAct 风格的“模型决策—工具执行—结果回灌—继续决策”循环。
- 结构化 Tool 定义、注册、查找、参数解析和结果模型。
- 演示工具：`echo_text` 回显和 `current_time` UTC 时间，用于验证协议。
- 一轮返回一个或多个 Tool Call 的兼容消息结构；本期按顺序执行。
- 最大迭代次数、整体超时、用户取消和正常完成条件。
- 重复调用检测和无进展保护。
- 统一运行事件，用于终端显示而不与 Agent 业务耦合。

## 5. 状态模型

一次 Run 至少经历：

```text
created → thinking → calling_tool → observing → thinking
        → completed | failed | canceled | limit_reached
```

`completed` 只表示模型给出不含工具调用的最终答复且消息协议完整。达到迭代上限时应进入 `limit_reached`，并输出已完成事项和未完成原因。

## 6. 功能需求

### FR-02-01 工具声明

每个工具包含唯一名称、面向模型的描述、JSON 参数结构和执行入口。重复名称在启动时失败，不能静默覆盖。

### FR-02-02 工具调用解析

Agent 必须验证工具名称、调用 ID 和参数 JSON。未知工具或非法参数转化为结构化失败 Observation，并允许模型纠正一次，而不是让进程崩溃。

### FR-02-03 Observation 回灌

工具结果必须与原调用 ID 关联，并保持消息顺序。结果包含成功状态、用户可读摘要和供模型判断的结构化信息。

### FR-02-04 迭代控制

默认最大迭代次数由配置提供，并有合理上限。达到限制时停止调用新工具，不把限制状态伪装成正常完成。

### FR-02-05 取消与超时

用户取消或整体超时后，Agent 不再发起新的模型请求或工具调用。当前可取消操作应收到取消信号。

### FR-02-06 无进展保护

当 Agent 连续多次以相同参数调用同一工具并获得相同结果时，应注入提醒或终止运行，避免无意义循环。

### FR-02-07 可观察事件

至少产生运行开始、模型请求、工具开始、工具结束、迭代完成、运行完成、运行失败和取消事件。事件不得包含模型私有思维过程或未脱敏凭据。

### FR-02-08 异常隔离

单个工具抛出异常时转换为失败 Observation；协议或不可恢复状态损坏时终止本次 Run，但保持 CLI 可继续接受新任务。

## 7. 终端体验

- 工具开始时显示名称和安全的参数摘要。
- 工具完成时显示成功、失败、耗时和结果摘要。
- 默认折叠冗长 Observation，调试模式可查看完整结果。
- 达到限制、失败或取消时明确说明状态，不能只结束输出。

## 8. 非目标

- 不实现真实文件系统和 Shell 工具。
- 不实现计划模式、并行工具或 Multi-Agent。
- 不持久化 Run，也不支持崩溃恢复。
- 不依赖模型自然语言中的 `Thought:` 文本来判断状态。

## 9. 异常与边界场景

- 模型同时返回文本和工具调用时，文本作为过程说明保留，工具调用继续执行。
- 工具结果过大时按预算截断，并告知原始大小与继续查询方式。
- 模型返回重复调用 ID 时拒绝该批次并终止协议错误。
- 未注册任何工具时仍可退化为 Phase 01 对话。
- 模型持续返回空响应时按可恢复错误重试有限次数后失败。

## 10. 验收标准

1. 模拟模型可以完成至少三步工具链并给出最终答案。
2. 未知工具、非法 JSON、工具异常和空响应均不会导致 CLI 崩溃。
3. 达到最大迭代、超时或取消后不再出现新的工具执行记录。
4. 相同工具与参数的重复循环能够被检测并停止。
5. 工具结果按调用 ID 和原始顺序回灌。
6. 运行事件足以重建用户可见的执行时间线。

## 11. 测试与验证

- 单元测试：工具注册、参数验证、结果关联、状态迁移和重复检测。
- 场景测试：成功链路、工具失败后纠正、迭代耗尽、取消、协议损坏。
- 性质检查：Run 进入终态后不能再次产生模型或工具事件。
- 本期采用 Fake Model/Tool 的确定性自动测试；按用户明确决定，不要求手工演示或录屏。

## 12. GitHub 交付物

- ReAct 状态图和消息时序图。
- 工具开发最小示例。
- 确定性 Fake Model 场景测试。
- 可复现的自动场景：正常完成、失败恢复和迭代限制；按用户明确决定，不要求终端录屏。

## 13. 下一阶段接口

Phase 03 将把真实本地编码工具注册到本期 Tool Registry。工具权限不会写入 Agent 主循环，而由后续独立策略层处理。

## 14. 变更记录

| 版本 | 日期 | 变更 |
|---|---|---|
| v1.0 | 2026-08-25 | 建立 ReAct Agent 产品范围与安全停止条件 |
| v1.1 | 2026-08-27 | 标记交付：受控演示工具、结构化协议和自动验收；免除人工演示/录屏，未创建版本标签 |

# Phase 03：本地编码工具 PRD

> 优先级：P0
> 状态：已规划
> 前置阶段：Phase 02
> 对应里程碑：M1 可用 Coding Agent

## 1. 阶段目标

为 Agent 提供完成小型开发任务所需的本地工具闭环：识别项目、浏览目录、读取文件、搜索代码、创建或修改文件、执行受控命令、查看 Git 差异并运行验证。本期形成第一个真实可演示的 Coding Agent，但安全审批由 Phase 04 完整交付。

## 2. 用户价值

- 用户可以用自然语言让 Agent 在真实仓库中定位并修改代码。
- 每次修改都能看到差异，并通过构建或测试确认结果。
- 工具输出受预算控制，不会把整个仓库塞进上下文。

## 3. 用户故事

- 作为开发者，我希望 Agent 找到指定功能对应的文件和代码位置。
- 作为开发者，我希望 Agent 只修改解决任务所需的文件。
- 作为开发者，我希望修改后自动运行相关测试并报告退出码。
- 作为审查者，我希望查看本轮生成的 Git diff 和涉及文件。

## 4. 本期范围

本期交付以下本地编码工具：

| 工具 | 用途 | 默认风险 |
|---|---|---|
| `list_dir` | 查看目录内容 | 只读 |
| `glob_files` | 按模式查找文件 | 只读 |
| `read_file` | 按行范围读取文本文件 | 只读 |
| `grep_code` | 精确搜索文本或正则 | 只读 |
| `write_file` | 创建或替换文本文件 | 写入 |
| `apply_patch` | 对已有文本做局部修改 | 写入 |
| `execute_command` | 执行构建、测试和辅助命令 | 高风险 |
| `git_diff` | 查看工作区差异 | 只读 |

产品实现可以合并或拆分内部工具，但对模型暴露的能力必须职责清晰，避免一个万能工具同时承担搜索、写入和命令执行。

## 5. 核心流程

```text
用户提交修改任务
  → Agent 定位候选文件
  → 按行读取必要内容
  → 生成局部变更
  → 应用修改
  → 查看差异
  → 运行相关构建或测试
  → 根据结果修正或总结
```

## 6. 功能需求

### FR-03-01 项目根识别

启动目录作为默认项目根；存在版本控制或构建标识时可以识别更准确的根目录。所有路径在执行前必须规范化。

### FR-03-02 目录与文件发现

目录结果包含名称、类型和相对路径，默认忽略构建产物、版本控制内部目录、依赖缓存和常见二进制目录。结果达到预算时返回 `partial` 标记。

### FR-03-03 范围读取

文本文件支持指定起止行。结果包含实际行号、文件总行数和是否截断。二进制、超大文件和无法解码文件必须给出明确错误。

### FR-03-04 精确搜索

搜索支持普通文本、大小写选项、文件模式和结果上限。优先使用系统高性能搜索工具，不可用时提供 Java 实现的兼容降级。

### FR-03-05 局部修改

修改已有文件优先使用基于上下文的补丁；无法唯一匹配时不得猜测位置或整文件覆盖。写入前后记录内容摘要，以便生成差异和后续恢复。

### FR-03-06 命令执行

命令明确包含工作目录和超时。结果返回退出码、耗时、标准输出、标准错误及截断状态。禁止以交互式无限等待方式运行。

### FR-03-07 差异查看

用户和 Agent 可以查看本轮或当前工作区差异。差异必须区分新增、修改、删除，并在过长时给出文件级摘要。

### FR-03-08 验证选择

Agent 应根据项目标识和修改范围选择最相关的构建、测试或静态检查命令。未找到可靠命令时先询问用户或说明人工验证方式。

### FR-03-09 结果预算

所有工具具有结果条数和字符数上限。截断结果必须告诉 Agent 如何缩小查询或继续读取，禁止静默丢失。

### FR-03-10 原子写入

文件写入使用临时文件与原子替换策略；失败时保留原文件，不能产生半写入内容。

## 7. 非目标

- 不允许项目根之外的路径访问。
- 不实现语义 RAG、LSP 或自动快照。
- 不自动执行 Git commit、push、merge、reset 或发布命令。
- 不编辑二进制文件。
- 不在未验证补丁唯一性的情况下整文件重写。

## 8. 异常与边界场景

- 文件在读取后被其他进程修改时，补丁应检测上下文不一致并失败。
- 命令输出持续增长时采用有界缓冲，并保留尾部错误信息。
- 软链接目标逃逸项目根时拒绝访问。
- 搜索工具未安装时自动降级，并在调试信息中标记实现来源。
- 工作区已有用户改动时不得覆盖或回退这些改动。
- 文件使用非 UTF-8 编码时只读操作可提示编码问题，写入操作默认拒绝。

## 9. 体验要求

- 只读工具以简洁行显示，写入和命令工具使用更醒目的状态。
- 修改完成后展示涉及文件和增删行摘要。
- 测试失败时突出退出码和关键错误，不用大量日志淹没结论。
- Agent 的最终答复引用实际相对路径，不使用模糊的“某文件”。

## 10. 验收标准

1. Agent 能在示例仓库中定位一个缺陷、应用最小修改并运行测试。
2. 读取、搜索和命令大输出均会按预算截断并带继续操作提示。
3. 补丁上下文不唯一或已过期时不会修改文件。
4. 原子写入失败后原文件内容保持不变。
5. 工作区已有未提交改动时，Agent 只增加本任务变更，不覆盖用户内容。
6. 最终总结包含文件列表、差异摘要、验证命令和实际结果。

## 11. 测试与验证

# Phase 04：安全与审批 PRD

> 优先级：P0
> 状态：已规划
> 前置阶段：Phase 03
> 对应里程碑：M1 可用 Coding Agent

## 1. 阶段目标

建立独立于 Agent 决策的安全与人工审批层。任何工具调用在执行前都必须经过风险分类、路径与命令硬策略、审批策略和审计记录，使用户能够在保持开发效率的同时控制文件写入和命令执行风险。

## 2. 安全模型

```text
模型提出工具调用
  → 参数校验
  → 系统硬策略检查
  → 风险与审批策略判断
  → 必要时请求用户决定
  → 工具执行
  → 脱敏审计
```

系统硬策略优先于用户批准。用户可以允许受支持的操作，但不能批准路径逃逸、已知凭据泄露或系统明确禁止的行为。

## 3. 用户故事

- 作为用户，我希望读取代码时尽量少被打断，但写入和命令执行前得到清晰提示。
- 作为用户，我希望能批准一次、拒绝、修改参数或在有限范围内本次会话放行。
- 作为用户，我希望查看 Agent 执行过哪些高风险操作，同时日志不暴露密钥。
- 作为维护者，我希望新增工具默认受到保护，而不是因漏配直接获得权限。

## 4. 本期范围

- 工具风险元数据与默认拒绝原则。
- 项目根路径围栏和符号链接逃逸检查。
- 命令快速拒绝、风险识别和作用域控制。
- 终端 HITL 审批交互。
- 会话级临时授权，不做永久全局放行。
- JSONL 操作审计与敏感参数脱敏。
- YOLO 模式的受限定义：减少可审批操作的交互，不绕过硬策略。

## 5. 风险分级

| 等级 | 示例 | 默认行为 |
|---|---|---|
| 只读 | 目录、文件、搜索、Git diff | 自动允许并审计摘要 |
| 中风险 | 新建或修改项目内文件 | 请求批准，可按工具或文件范围临时放行 |
| 高风险 | 执行命令、删除、恢复快照、外部写操作 | 每次批准或精确规则放行 |
| 禁止 | 项目外写入、凭据外传、破坏性系统命令 | 直接拒绝，不可批准 |

## 6. 功能需求

### FR-04-01 默认保护

未声明风险等级的新工具按高风险处理。权限配置错误时采取更保守行为。

### FR-04-02 路径围栏

所有文件系统参数在执行前解析为规范路径，并检查绝对路径、`..`、符号链接和目标父目录。项目根之外的写入始终拒绝。

### FR-04-03 命令策略

命令策略至少识别递归删除、磁盘与权限修改、强制 Git 操作、包发布、网络上传、进程管理和可能包含凭据的参数。命令黑名单仅为辅助，不能替代工作目录和权限隔离。

### FR-04-04 审批信息

审批提示展示工具名称、风险等级、目标文件或工作目录、命令摘要、预期影响和拒绝后的处理方式。敏感字段必须掩码。

### FR-04-05 审批决策

支持：批准一次、拒绝、跳过当前步骤、修改可编辑参数后再执行、在当前 Run 的明确范围内放行。取消审批等同拒绝。

### FR-04-06 授权作用域

临时授权必须绑定 Run、工具及必要的路径或命令范围。Run 结束、模式切换或权限上下文变化后自动失效。

### FR-04-07 审计记录

审计至少记录时间、Run ID、工具、风险、参数摘要、策略结果、用户决定、执行结果和耗时。日志写入失败不能静默放行高风险操作。

### FR-04-08 凭据脱敏

对 Key、token、password、secret、Authorization、Bearer、Cookie 等名称和值模式进行脱敏。原始凭据不得进入终端审批文案和审计文件。

### FR-04-09 非交互模式

无终端审批能力时，只读操作可按策略执行；所有需要用户批准的操作默认拒绝，除非存在预先配置的精确规则。

### FR-04-10 策略可解释性

拒绝结果必须包含规则类型和可行替代方案，例如缩小路径、改用只读命令或由用户手工执行。

## 7. 非目标

- 本期不提供容器、虚拟机或操作系统级沙箱。
- 不承诺识别任意 Shell 组合中的所有危险语义。
- 不允许用 YOLO 模式绕过系统硬策略。
- 不存储永久“允许所有命令”规则。
- 不审计文件的完整敏感内容，只记录必要摘要。

## 8. 异常与边界场景

- 审批期间收到 Ctrl+C 时拒绝当前操作并取消或返回 Agent。
- 用户修改参数后必须重新执行参数校验和硬策略检查。
- 同一工具参数变化后不得复用旧批准。
- 审计目录不可写时，高风险工具拒绝执行并提示修复方式。
- 命令使用 Shell 管道、重定向或子命令时按完整文本提高风险，不能只检查首个单词。
- 大小写或编码变形的敏感字段仍应尽可能脱敏。

## 9. 体验要求

- 审批提示使用简短语言，默认聚焦影响，不展示大段 JSON。
- 用户可以展开查看完整非敏感参数。
- 拒绝后 Agent 获得结构化 Observation，可以提出更安全方案。
- 状态区明确显示当前是普通审批模式还是受限 YOLO 模式。

## 10. 验收标准

1. 项目根外写入、符号链接逃逸和明确禁止命令均不可通过用户批准执行。
2. 只读工具默认不打断；写入和高风险命令按策略请求批准。
3. 批准一次不会扩展为其他工具、其他路径或后续 Run 的授权。
4. 修改参数后会重新执行全部检查。
5. 审计日志可以还原决策时间线，但不出现测试用真实凭据。
6. 非交互模式下所有待审批操作默认拒绝。
7. 新增未标风险工具会以高风险处理。

## 11. 测试与验证

- 决策表测试：工具类型 × 风险 × 模式 × 用户选择。
- 路径测试：相对路径、绝对路径、`..`、软链接、尚不存在的目标。
- 命令测试：安全构建、递归删除、强制 Git、管道重定向和环境变量。
- 脱敏测试：常见字段名、Bearer、URL 参数和嵌套 JSON。
- 手工演示：批准文件修改、拒绝危险命令、查看脱敏审计。
