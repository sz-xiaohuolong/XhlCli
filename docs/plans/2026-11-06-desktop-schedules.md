# 桌面定时任务实施计划

用户要求复用 task，在桌面侧边栏提供与截图相近的定时任务。当前范围是应用运行时的每日任务；关闭窗口仍运行，退出应用不运行。结果保存在本机，不添加云服务、自动发消息或系统级唤醒。

## 范围与行为

- 创建、编辑每日任务：标题、任务内容、已添加的项目、已配置的模型、HH:mm 时间、IANA 时区。时区保存后固定，不随旅行自动改变。
- 左侧分组显示启用/暂停的任务；右侧显示计划、下一次执行、历史结果。提供暂停/恢复、立即运行、取消当前执行和删除；运行中不能删除。
- 创建或编辑后从下一个计划时间开始；恢复暂停任务同样从未来开始。用户已明确选择：应用休眠/退出错过的未触发计划直接跳过，恢复后等待下一次计划时间；不重试已经失败/中断的执行。
- 同一计划不并发执行。每次运行生成独立 task，并复用只读 BackgroundTaskRunner；每个项目串行执行定时 task。手动运行不改变下一次计划。
- 计划与 task 入队在同一 SQLite 事务中提交，避免重启产生重复触发。夏令时不存在的时间顺延、重复时间只执行一次。
- 后台输出显示完成/失败/取消及部分结果，错误不得使整个调度线程停止。项目不可访问时记录失败并等待下一次，不反复尝试模型。

## 技术基线与文件

沿用 Java 21、SQLite JDBC、Jackson、JUnit，桌面 Electron 45.2.3 / React 19.3.1 / esbuild。无新依赖。遵循根 AGENTS，保留现有斜杠命令等未提交改动，UI 采用独立组件减少冲突。本轮不代提交其他会话改动。

| 任务 | 文件与职责 | 验收 |
|---|---|---|
| S1 | runtime/task/DailySchedule、ScheduledTaskService：时区、事务、task 复用与恢复 | 固定 Clock、跨日/DST、重启、并发/暂停、失败与取消 |
| S2 | desktop/DesktopSchedules，DesktopService 和 Electron 私有协议入口 | 已绑定项目、模型、只读运行、状态和结果查询 |
| S3 | desktop/src/ScheduledTasks.jsx、schedules.css，主侧栏入口 | 空态/表单/列表/详情、错误保留输入、键盘焦点、窄窗口 |
| S4 | 全量验证、真实 Electron 离线验收及文档 | Java verify、Node test、前端构建、成品启动；记录真实结果 |

时间规则依据 Java 21 ZonedDateTime 的 gap/overlap 行为；事务遵循 SQLite commit/rollback。React 异步刷新使用 effect 清理避免旧响应覆盖新选择。源码、既有测试与官方文档为技术依据。

计划库使用桌面专用 `.xhlcli/desktop/schedules.db`，不迁移原 CLI task 数据库或桌面 state.json。数据是本机私有计划与结果；不存模型密钥。回滚代码可保留该库，旧版不会执行其中计划。

## 验收口径

AC-S01 创建保存后重启仍可见、下一次时间正确；AC-S02 到点只入队一次，休眠/退出错过时间跳过、不补跑；AC-S03 暂停不触发、恢复从未来开始、手动运行不改日程；AC-S04 复用真实 task 执行/取消/结果与只读权限；AC-S05 项目和模型校验、无效字段拒绝且原计划不变；AC-S06 UI 空态、操作和错误反馈可用；AC-S07 退出停止、重启不重做已失联执行。实际进度与证据分别记入 PROGRESS 与 engineering/desktop-schedules-verification.md。
