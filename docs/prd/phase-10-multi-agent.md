# Phase 10：Multi-Agent 协作 PRD

> 优先级：P1
> 状态：已规划
> 前置阶段：Phase 08、09
> 对应里程碑：M2 复杂任务智能

## 1. 阶段目标

为适合角色分工的复杂任务提供 Multi-Agent 协作模式。统一编排器负责拆解、分发、上下文交接和结果汇总，专职 Agent 分别承担规划、实现和审查；审查反馈可以触发有限修正，最终仍由一个执行主体对用户负责。

## 2. 用户价值

- 复杂任务可以由不同职责的 Agent 分别思考，降低单一上下文中的角色冲突。
- 审查者基于需求和实际差异进行质量检查，而不是实现者自我确认。
- 用户能看到任务由谁处理、当前状态和审查结论，不需要理解内部消息细节。

## 3. 适用边界

Multi-Agent 适合跨模块、有明确子任务或需要独立审查的工作。简单搜索、小文件修改和单一测试修复继续使用 ReAct；产品不得为了展示“多 Agent”而把简单任务强制拆分。

## 4. 角色

| 角色 | 主要责任 | 禁止事项 |
|---|---|---|
| Planner | 理解目标、拆分任务、定义依赖和验收 | 不直接写代码 |
| Worker | 在分配范围内实现并验证 | 不扩展未授权范围 |
| Reviewer | 对照需求、差异和测试证据审查 | 不以无证据结论批准 |
| Orchestrator | 调度、交接、状态、重试和汇总 | 不绕过权限与计划约束 |

## 5. 本期范围

- `/team <任务>` 显式入口及适用性提示。
- 角色 Prompt 与能力边界。
- 计划任务到 Worker 的分配。
- 最小化上下文交接包。
- Reviewer 审查与结构化结论。
- 最多有限次数的反馈修正循环。
- 独立任务并行、文件冲突串行。
- 团队执行时间线和最终结果汇总。

## 6. 功能需求

### FR-10-01 团队任务创建

Orchestrator 基于用户目标和仓库只读探索创建执行计划。用户确认后才启动产生写操作的 Worker。

### FR-10-02 角色隔离

每个角色使用独立会话上下文和角色 Prompt。不得把所有 Agent 完整历史互相复制；只传递任务所需的交接包。

### FR-10-03 交接包

交接至少包含任务目标、允许范围、依赖结果、关键代码引用、验收方式、全局约束和剩余 Token 预算。文件内容优先按引用按需读取。

### FR-10-04 Worker 执行

Worker 只能处理被分配任务。需要扩大范围或发现计划错误时返回阻塞原因，由 Orchestrator 决定重规划，不能私自修改其他模块。

### FR-10-05 Reviewer 输入

Reviewer 获得原始需求、任务验收标准、实际 diff、验证命令和结果。不得只阅读 Worker 的自然语言总结。

### FR-10-06 审查结论

结论为 `approved`、`changes_requested` 或 `blocked`，并包含按严重程度排序、带文件证据的发现。没有可操作问题时不制造无意义意见。

### FR-10-07 修正循环

`changes_requested` 返回原 Worker 或新修正任务，最多重试可配置次数。超过限制后整体进入失败或等待用户决定。

### FR-10-08 冲突与并行

无依赖且修改范围不重叠的 Worker 可以并行。冲突任务必须串行或重新分区；实际冲突出现时停止受影响任务并保留差异。

### FR-10-09 统一权限

所有角色共享同一工具注册和安全策略。角色身份不能提高权限，审批显示发起角色和任务。

### FR-10-10 最终汇总

Orchestrator 输出任务完成情况、每个角色贡献、修改文件、审查结论、验证证据和未解决风险。内部对话不默认全部展示。

## 7. 非目标

- 不允许 Agent 自由创建无限层级子 Agent。
- 不支持跨机器分布式协作。
- 不让多个 Worker 并行修改同一文件。
- 不把角色数量作为成功指标。
- 不用 Reviewer 的自然语言批准替代真实测试。

## 8. 异常与边界场景

- Planner 无法拆出两个有意义子任务时建议回到 ReAct 或 Plan 模式。
- Worker 失败不自动取消独立 Worker，但阻塞依赖任务。
- Reviewer 请求超出原需求的改动时由 Orchestrator 拒绝或请求用户扩展范围。
- 交接包超预算时保留目标、约束、证据引用和未完成项，压缩解释性历史。
- 用户取消后所有角色停止获取新任务。

## 9. 验收标准

1. 示例跨模块任务能由 Planner、两个 Worker 和 Reviewer 完成闭环。
2. Reviewer 使用实际 diff 和测试结果，能够发现预置缺陷并要求修正。
3. 交接包不包含其他 Agent 的全部历史，且足以完成任务。
4. Worker 超出修改范围时被阻止并返回可解释原因。
5. 修正循环达到限制后不会无限继续。
6. 简单任务进入 `/team` 时能提示不必要并允许用户选择继续或降级。

## 10. 测试与验证

- 单元测试：角色权限、交接包、审查状态和重试计数。
- 场景测试：成功审查、发现缺陷、范围扩张、Worker 失败和用户取消。
- 并发测试：独立 Worker 与冲突文件任务。
- 手工演示：两模块功能开发和独立审查。
