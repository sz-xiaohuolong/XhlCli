# Phase 08：Plan-and-Execute PRD

> 优先级：P1
> 状态：已规划
> 前置阶段：Phase 03–07
> 对应里程碑：M2 复杂任务智能

## 1. 阶段目标

为跨文件、多步骤和高风险任务提供显式计划模式。Agent 在修改前生成可审阅的任务列表与依赖关系，用户确认后逐步执行，并在失败或新信息出现时更新计划。

## 2. 用户价值

- 用户能在代码变更前了解 Agent 准备做什么以及影响哪些模块。
- 复杂任务按照依赖顺序执行，每一步都有状态和验证结果。
- 失败不会让整个任务失去方向，可以跳过、重试或重新规划。

## 3. 用户故事

- 作为用户，我希望输入 `/plan <任务>` 后先看到计划，再决定是否执行。
- 作为用户，我希望修改计划、补充约束或取消，而不是只能接受模型方案。
- 作为用户，我希望知道哪些步骤已完成、失败、阻塞或未开始。

## 4. 本期范围

- 计划模式入口和复杂度判断建议。
- 结构化任务、依赖、验收方式和风险信息。
- 计划审阅：执行、取消、补充要求并重规划。
- DAG 合法性检查与顺序执行。
- 步骤状态、结果和证据汇总。
- 有限重试与失败后重规划。
- 计划变更历史和最终对照总结。

## 5. 计划数据要求

每个任务至少包含：唯一 ID、目标、依赖 ID、预期产物、允许修改范围、验证方式、风险等级和当前状态。计划必须有用户目标摘要与全局完成条件。

## 6. 功能需求

### FR-08-01 计划生成

Planner 在生成计划前可以使用只读搜索工具获取仓库信息。计划粒度应使单个步骤可以独立验证，避免“完成所有开发”一类不可执行任务。

### FR-08-02 依赖校验

执行前检查任务 ID 唯一、依赖存在且无环。非法计划返回 Planner 修正，不进入执行。

### FR-08-03 用户审阅

用户可以执行、取消、展开详情或补充约束。补充约束后生成新版本计划，并突出与上一版差异。

### FR-08-04 步骤执行

只有全部依赖完成的任务可以开始。每一步使用受限目标和允许范围进入 Agent，完成后执行该步验证并保存结果。

### FR-08-05 状态管理

任务状态至少包括 `pending`、`ready`、`running`、`completed`、`failed`、`skipped`、`blocked`、`canceled`。终态任务不能被意外重复执行。

### FR-08-06 失败处理

步骤失败后提供重试、跳过、取消或基于新证据重规划。重试有次数限制；跳过导致依赖不满足时，下游任务转为阻塞。

### FR-08-07 范围控制

执行 Agent 获得当前步骤目标、必要上下文和全局约束，不默认获得修改所有模块的权限。超出计划的修改需停止并请求重规划或用户批准。

### FR-08-08 最终汇总

结束时按原计划列出每个步骤状态、修改文件、验证证据、失败项和未实现范围，并说明计划是否发生变化。

## 7. 非目标

- 本期不并行执行任务。
- 不实现 Multi-Agent 角色协作。
- 不允许 Planner 绕过工具权限与审批。
- 不承诺计划一经确认绝不变化。
- 不持久化跨进程恢复计划。

## 8. 异常与边界场景

- 空计划、循环依赖和不存在依赖必须在执行前拒绝。
- 用户取消计划时不执行任何写操作。
- 执行中项目被外部修改时，受影响步骤重新验证上下文。
- 重新规划不能把已完成任务悄然改成未完成，必须保留历史。
- 最后一步验证失败时整体任务不能标记完成。

## 9. 验收标准

1. 跨三个文件的示例任务可以生成合法计划并在确认后按依赖完成。
2. 用户补充限制后能看到计划差异，旧计划不会被静默覆盖。
3. 循环依赖和缺失依赖不会进入执行。
4. 失败步骤可以有限重试或触发重规划，下游状态正确。
5. 计划步骤超出允许修改范围时被拦截。
6. 最终报告能逐项对应计划和验证证据。

## 10. 测试与验证

- 单元测试：DAG 校验、状态迁移、依赖解锁、阻塞传播。
- 场景测试：成功计划、用户修改、步骤失败、重试、跳过和取消。
- 集成测试：真实临时仓库的跨文件修改任务。
- 手工演示：计划审阅和失败后重规划。
