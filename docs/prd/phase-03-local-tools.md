# Phase 03：本地编码工具 PRD

> 优先级：P0
> 状态：已规划
> 前置阶段：Phase 02
> 对应里程碑：M1 可用 Coding Agent

## 1. 阶段目标

为 Agent 提供完成小型开发任务所需的本地工具闭环：识别项目、浏览目录、读取文件、搜索代码、创建或修改文件、执行受控命令、查看 Git 差异并运行验证。本期形成第一个真实可演示的 Coding Agent，但安全审批由 Phase 04 完整交付。

## 2. 用户价值

- 用户可以用自然语言让 Agent 在真实仓库中定位并修改代码。
- 每次修改都能看到差异，并通过构建或测试确认结果。
- 工具输出受预算控制，不会把整个仓库塞进上下文。

## 3. 用户故事

- 作为开发者，我希望 Agent 找到指定功能对应的文件和代码位置。
- 作为开发者，我希望 Agent 只修改解决任务所需的文件。
- 作为开发者，我希望修改后自动运行相关测试并报告退出码。
- 作为审查者，我希望查看本轮生成的 Git diff 和涉及文件。

## 4. 本期范围

本期交付以下本地编码工具：

| 工具 | 用途 | 默认风险 |
|---|---|---|
| `list_dir` | 查看目录内容 | 只读 |
| `glob_files` | 按模式查找文件 | 只读 |
| `read_file` | 按行范围读取文本文件 | 只读 |
| `grep_code` | 精确搜索文本或正则 | 只读 |
| `write_file` | 创建或替换文本文件 | 写入 |
| `apply_patch` | 对已有文本做局部修改 | 写入 |
| `execute_command` | 执行构建、测试和辅助命令 | 高风险 |
| `git_diff` | 查看工作区差异 | 只读 |

产品实现可以合并或拆分内部工具，但对模型暴露的能力必须职责清晰，避免一个万能工具同时承担搜索、写入和命令执行。

## 5. 核心流程

```text
用户提交修改任务
  → Agent 定位候选文件
  → 按行读取必要内容
  → 生成局部变更
  → 应用修改
  → 查看差异
  → 运行相关构建或测试
  → 根据结果修正或总结
```

## 6. 功能需求

### FR-03-01 项目根识别

启动目录作为默认项目根；存在版本控制或构建标识时可以识别更准确的根目录。所有路径在执行前必须规范化。

### FR-03-02 目录与文件发现

目录结果包含名称、类型和相对路径，默认忽略构建产物、版本控制内部目录、依赖缓存和常见二进制目录。结果达到预算时返回 `partial` 标记。

### FR-03-03 范围读取

文本文件支持指定起止行。结果包含实际行号、文件总行数和是否截断。二进制、超大文件和无法解码文件必须给出明确错误。

### FR-03-04 精确搜索

搜索支持普通文本、大小写选项、文件模式和结果上限。优先使用系统高性能搜索工具，不可用时提供 Java 实现的兼容降级。

### FR-03-05 局部修改

修改已有文件优先使用基于上下文的补丁；无法唯一匹配时不得猜测位置或整文件覆盖。写入前后记录内容摘要，以便生成差异和后续恢复。

### FR-03-06 命令执行

命令明确包含工作目录和超时。结果返回退出码、耗时、标准输出、标准错误及截断状态。禁止以交互式无限等待方式运行。

### FR-03-07 差异查看

用户和 Agent 可以查看本轮或当前工作区差异。差异必须区分新增、修改、删除，并在过长时给出文件级摘要。

### FR-03-08 验证选择

Agent 应根据项目标识和修改范围选择最相关的构建、测试或静态检查命令。未找到可靠命令时先询问用户或说明人工验证方式。

### FR-03-09 结果预算

所有工具具有结果条数和字符数上限。截断结果必须告诉 Agent 如何缩小查询或继续读取，禁止静默丢失。

### FR-03-10 原子写入

文件写入使用临时文件与原子替换策略；失败时保留原文件，不能产生半写入内容。

## 7. 非目标

- 不允许项目根之外的路径访问。
- 不实现语义 RAG、LSP 或自动快照。
- 不自动执行 Git commit、push、merge、reset 或发布命令。
- 不编辑二进制文件。
- 不在未验证补丁唯一性的情况下整文件重写。

## 8. 异常与边界场景

- 文件在读取后被其他进程修改时，补丁应检测上下文不一致并失败。
- 命令输出持续增长时采用有界缓冲，并保留尾部错误信息。
- 软链接目标逃逸项目根时拒绝访问。
- 搜索工具未安装时自动降级，并在调试信息中标记实现来源。
- 工作区已有用户改动时不得覆盖或回退这些改动。
- 文件使用非 UTF-8 编码时只读操作可提示编码问题，写入操作默认拒绝。

## 9. 体验要求

- 只读工具以简洁行显示，写入和命令工具使用更醒目的状态。
- 修改完成后展示涉及文件和增删行摘要。
- 测试失败时突出退出码和关键错误，不用大量日志淹没结论。
- Agent 的最终答复引用实际相对路径，不使用模糊的“某文件”。

## 10. 验收标准

1. Agent 能在示例仓库中定位一个缺陷、应用最小修改并运行测试。
2. 读取、搜索和命令大输出均会按预算截断并带继续操作提示。
3. 补丁上下文不唯一或已过期时不会修改文件。
4. 原子写入失败后原文件内容保持不变。
5. 工作区已有未提交改动时，Agent 只增加本任务变更，不覆盖用户内容。
6. 最终总结包含文件列表、差异摘要、验证命令和实际结果。

## 11. 测试与验证

- 单元测试：路径规范化、范围读取、补丁匹配、输出截断和命令结果。
- 集成测试：临时 Git 仓库中执行完整修改和 diff 流程。
- 故障测试：命令超时、进程取消、写入失败、并发修改和软链接逃逸。
- 基准场景：修改 Java 方法并通过对应 JUnit 测试。

## 12. GitHub 交付物

- 工具清单和参数示例。
- 示例仓库及确定性任务脚本。
- 一段“定位—修改—测试—总结”完整终端录屏。
- 已知限制：本期审批仅为临时保护，完整策略在 Phase 04。

## 13. 下一阶段接口
