# Phase 06：代码精确检索 PRD

> 优先级：P0
> 状态：已规划
> 前置阶段：Phase 03、05
> 对应里程碑：M1 可用 Coding Agent

## 1. 阶段目标

把“实时探索代码库”建设为 Agent 的默认代码理解方式。通过文件发现、精确文本搜索和按范围读取，让 Agent 用最少上下文定位符号、配置、调用位置和测试，并形成可评测的搜索质量基线。

## 2. 用户价值

- 面对陌生仓库时，Agent 可以快速引用真实文件和行号，而不是猜测结构。
- 搜索结果过多时能引导缩小范围，不会把大段无关内容送入模型。
- 没有额外模型或索引服务也能使用核心代码检索能力。

## 3. 搜索原则

```text
glob_files 找候选文件
  → grep_code 定位符号/字符串
  → read_file 读取最小必要行段
  → 如结果不足，缩小或扩展搜索
  → 精确方法失败后才考虑语义检索
```

## 4. 本期范围

- 面向 Agent 优化 `glob_files`、`grep_code` 和 `read_file` 的参数与结果。
- `ripgrep` 优先、Java 扫描降级。
- 忽略规则、文件类型和大小限制。
- 搜索结果预算、`partial`、`suggested_reads` 和继续查询建议。
- 代码搜索系统提示规则。
- 确定性 Golden Set 和搜索质量报告。
- 用户命令 `/search-text` 或等价入口用于人工验证。

## 5. 功能需求

### FR-06-01 候选文件发现

支持 glob、扩展名、包含目录和排除目录。默认尊重 `.gitignore`，并排除版本控制内部目录、依赖目录、构建产物和二进制文件。

### FR-06-02 精确搜索

支持普通文本与正则、大小写、固定字符串、上下文行数、文件模式、最大结果数和最大字符数。无结果与执行失败必须区分。

### FR-06-03 行范围读取

搜索结果应提供适合继续读取的文件和行范围。读取时带稳定行号，避免 Agent 为查看附近上下文读取整个文件。

### FR-06-04 实现降级

检测到本机 `rg` 时使用高性能实现；不可用时自动使用 Java 实现。相同查询的语义和结果排序应尽量一致。

### FR-06-05 结果预算

达到条数或字符预算时返回 `partial: true`、已返回数量和缩小建议。不能把截断结果表述成“全部结果”。

### FR-06-06 搜索策略提示

Agent 在询问当前仓库、当前代码或当前文件时优先使用本地搜索，不因问题包含“当前”而错误触发联网搜索。

### FR-06-07 引用来源

最终解释必须引用相对路径和起始行；无法确认时明确标注推断，不能伪造路径或行号。

### FR-06-08 搜索评测集

建立覆盖 Java 项目的确定性任务：找类定义、接口实现、方法调用、配置键、测试、命令入口和不存在符号。每个任务定义期望文件或结果性质。

## 6. 非目标

- 不构建向量索引或 AST 关系图。
- 不保证理解运行时动态调用和反射关系。
- 不用搜索工具自动修改文件。
- 不索引项目根之外或被忽略的内容。

## 7. 异常与边界场景

- 正则非法时返回参数错误，不回退为普通文本。
- 二进制或超大单行文件默认跳过并报告数量。
- 用户明确包含被忽略目录时可在安全范围内覆盖默认忽略规则。
- 文件在搜索与读取间变化时行号可能失效，修改前必须重新读取上下文。
- 搜索无结果时建议同义词、大小写或文件模式变化，再考虑 RAG。

## 8. 非功能要求

- 中型仓库的常见精确查询应在 1 秒内开始返回结果。
- 相同仓库和参数下结果顺序确定。
- Java 降级实现的 Golden Set 正确性不能显著低于 `rg` 实现。
- 搜索工具输出不包含 ANSI 控制符和不可解析的混合格式。

## 9. 验收标准

1. Golden Set 覆盖的存在性查询全部找到期望文件，不存在性查询不伪造结果。
2. `rg` 可用和不可用时均能完成核心搜索场景。
3. 大结果返回 `partial` 与继续查询建议，并符合字符预算。
4. Agent 回答代码位置时引用实际相对路径和行号。
5. 当前仓库问题不会自动触发网络工具。
6. 搜索、读取和补丁修改可以组成一个稳定的小型任务闭环。

## 10. 测试与验证

- Golden Set：固定仓库、固定查询和期望文件。
- 对比测试：`rg` 与 Java 实现在统一语义下的结果。
- 性能记录：冷缓存与热缓存查询耗时。
- 手工演示：不建立索引的陌生仓库功能定位。
