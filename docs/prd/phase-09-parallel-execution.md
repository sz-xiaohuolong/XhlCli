# Phase 09：并行执行 PRD

> 优先级：P1
> 状态：已规划
> 前置阶段：Phase 08
> 对应里程碑：M2 复杂任务智能

## 1. 阶段目标

在不破坏消息顺序、权限控制和文件一致性的前提下，为互不依赖的只读工具和计划任务提供有界并行执行，减少复杂任务的等待时间，并建立统一取消与超时机制。

## 2. 用户价值

- 多个独立搜索、读取或测试可以同时进行，复杂任务更快完成。
- 用户能够查看并行任务的独立状态，并一键取消整个 Run。
- 单个任务失败不会导致其他结果丢失，汇总顺序保持稳定。

## 3. 并行原则

- 默认只并行只读或已证明互不冲突的操作。
- 写入同一文件、共享非线程安全状态或有依赖关系的任务必须串行。
- 并行是执行优化，不改变工具调用和计划的逻辑结果顺序。
- 所有子任务继承同一 Run 的权限边界、取消信号和上下文预算。

## 4. 本期范围

- Java 21 有界并发执行器。
- 同一模型响应中多个工具调用的并行资格判断。
- DAG 同一依赖层任务的并行执行。
- 结果按原调用或计划顺序归并。
- Run 级取消、任务级超时和整体截止时间。
- 并发数量配置、状态展示和耗时指标。
- 文件冲突与资源互斥的保守检测。

## 5. 功能需求

### FR-09-01 并行资格

工具声明只读性、资源键和是否可并行。未声明的新工具默认串行。计划任务根据修改范围和依赖关系判断，无法证明独立时串行。

### FR-09-02 有界并发

默认最大并发数为保守值，用户可在安全范围内配置。不得为每个任务无限创建平台线程或无上限排队。

### FR-09-03 稳定结果顺序

即使执行完成顺序不同，回灌给模型的工具结果仍按原 Tool Call 顺序；计划汇总按计划任务顺序展示。

### FR-09-04 取消传播

用户取消 Run 后，停止调度新任务，并向运行中的模型请求、命令和可取消工具传播信号。已完成结果保留并标记。

### FR-09-05 超时层级

单工具超时、计划步骤超时和 Run 截止时间分别配置。子任务超时转换为结构化失败，不无限占用执行槽。

### FR-09-06 冲突控制

多个任务声明同一写资源时不得并行。任务实际访问超出声明范围时停止该任务并要求重新规划。

### FR-09-07 失败隔离

一个并行任务失败时，其他独立任务可以完成；依赖失败任务的下游任务保持阻塞。整体策略由计划模式决定。

### FR-09-08 状态展示

终端显示运行数、等待数、完成数和失败数。默认不让多个线程直接竞争标准输出，所有输出通过统一事件通道渲染。

## 6. 非目标

- 不实现分布式任务调度。
- 不并行修改同一文件。
- 不保证外部命令自身线程安全。
- 不用并行掩盖慢模型或错误计划。
- 不在本期持久化任务队列。

## 7. 异常与边界场景

- 并行任务同时请求用户审批时应排队显示，避免交互混乱。
- 任务取消后迟到结果不得改变终态，但可记录为已忽略事件。
- 执行器饱和时任务排队并展示状态，不能丢弃。
- 一个任务发生不可恢复协议错误时取消关联批次，保留已完成证据。
- 终端不支持动态状态时降级为按事件输出。

## 8. 验收标准

1. 三个独立延迟工具在并发开启时总耗时显著低于串行基线。
2. 并行完成顺序随机变化时，模型收到的结果顺序仍确定。
3. 同一文件的两个写任务不会并行。
4. 取消 Run 后不再调度新任务，运行中可取消任务收到信号。
5. 单任务失败不丢失其他独立任务的成功结果。
6. 并发数始终不超过配置上限。

## 9. 测试与验证

- 并发测试：闩锁控制完成顺序并验证稳定归并。
- 冲突测试：相同与不同资源键的调度行为。
- 取消测试：排队、运行中和完成边界的竞态。
- 压力测试：大量短任务下无死锁、线程泄漏和无界内存增长。
- 手工演示：并行搜索多个模块并按顺序汇总。

## 10. GitHub 交付物

- 串行/并行基准对比。
