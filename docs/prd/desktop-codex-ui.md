# XhlCLI 桌面 MVP 需求与验收基线

为 XhlCLI 提供对齐用户当前安装版 Codex 的 macOS 桌面界面，保留 XhlCLI 名称与执行引擎。首版完成项目、独立会话、真实流式编程、界面审批、取消、历史续聊和改动查看/安全撤销。自动化、插件管理及其他扩展页面后续补齐。

日期：2026-11-06。状态：**MVP 范围已冻结，用户已授权开发、桌面测试及推送远程**。最新指示以两张用户截图为主界面与设置页参照，重点适配已有 XhlCLI，不扩建完整 Codex 功能。原始调研见[研究记录](../engineering/2026-11-06-codex-desktop-research.md)，实际验证与限制见[验收证据](../engineering/desktop-mvp-verification.md)。本次不发布 Tag 或 Release。

## 1. 背景与成功定义

现有 XhlCLI 提供终端 Agent 能力，用户希望在熟悉的 Codex 桌面交互中使用它。成功意味着能够在图形界面真实完成编程任务，并可靠地知道执行状态、权限请求、代码改动和历史上下文。

“一致”包含指定页面的布局、视觉及主要操作流程，不承诺复现模型回答内容或首版范围之外的能力。视觉结论必须基于用户当前安装版的固定参照材料，不能用公开演示或主观相似代替验收。

## 2. 已确认目标与首版边界

用户在本次会话三轮问答中确认：

| 决定 | 已确认内容 |
|---|---|
| Q1 | 以当前电脑安装的 Codex 为参照；保留 XhlCLI 名称 |
| Q2 | macOS 首版，优先可实际使用的编程核心闭环 |
| Q3 | 完整消息、工具结果及改动记录持久保存；重开后可续聊；被退出打断的执行标记中断，不自动重跑 |
| Q4 | 多项目、多会话切换；同一工作目录同一时间只执行一个任务 |
| Q5 | 文件列表、逐文件 diff、打开文件、确认后安全撤销本轮改动；保护用户原有修改 |
| Q6 | 复用现有多 Provider 配置，提供模型切换、API Key 设置及连接测试 |
| Q7 | 展示 Agent 的命令和输出，支持打开外部终端；完整内置终端后续实现 |
| Q8 | 首版普通编程模式，支持文字、文件引用和图片附件；Plan/Team 专门入口后续补齐，保留底层已有能力 |

首版不包含 worktree 并行管理、Git 提交/推送/PR 按钮、自动化、插件管理页及完整内置终端。其他平台、云端任务与账户同步不纳入本次已确认交付范围。

## 3. 用户与主要流程

目标用户为使用 macOS、需要在本地代码目录完成编程任务的开发者。

主要流程：选择或添加项目 → 创建会话 → 选择模型 → 输入需求/引用文件/附加图片 → 观察生成与工具过程 → 响应审批 → 检查结果与 diff → 必要时安全撤销 → 重新打开应用继续该会话。

## 5. 详细行为与验收

### REQ-D01：桌面框架与项目

从桌面入口选择本地项目，建立会话；从侧栏切换项目或会话。项目上下文必须与实际执行目录一致。视图位置、尺寸、颜色、字体、图标、菜单及快捷键以本次用户提供的两张截图为准。

- **AC-D01**：给定两个不同目录的项目，在各自会话读取同名文件，返回内容分别来自对应项目；切换界面不改变已启动任务的工作目录。
- **AC-D02**：给定空项目列表，能从界面添加本地目录并创建会话；目录不可访问时明确显示原因，不进入错误目录执行。
- **AC-D03**：以用户提供的主聊天、设置截图为参照，检查浅色框架、窄功能栏、项目侧栏、居中聊天、底部输入框与分组设置行。按用户最新 MVP 指示验收核心页面，不声明全功能或逐像素一致。

### REQ-D02：完整历史与续聊

每个会话具有独立消息和工具记录，关联固定项目。退出重开后可以阅读完整记录并继续对话。模型续聊必须恢复必要上下文，而不只是把旧文字画在屏幕上。历史中的审批决定作为记录保留，不代表未来工具调用自动获得授权。

- **AC-D04**：在会话 A 告知一个只存在于对话中的标记，结束一轮后退出重开，继续询问标记时上下文可用；会话 B 不包含 A 的历史。
- **AC-D05**：完成一轮含工具执行和文件改动的任务后退出重开，消息、工具结果和当时的改动记录仍能查看。
- **AC-D06**：执行中退出导致任务停止或进程异常结束，重开后显示已中断及已保存部分；不自动再次执行命令或重新发送任务。

“完整”包含可展示的消息、工具输入/结果和改动证据，不要求持久保存供应商未返回的内部推理。图片按第 9 节的已采用规则处理。

### REQ-D03：普通编程聊天

支持输入文字、引用文件和附加图片，通过 XhlCLI 普通编程能力真实执行。生成过程接收实际增量，工具执行按真实状态呈现。切换会话不使两者输出混合。

- **AC-D07**：给定能分段返回内容的测试模型，第一批内容在最终回复结束前显示，最终文本顺序正确；不是拿完整回复做打字动画。
- **AC-D08**：给定可读文件引用，模型能收到对应文件上下文；引用失效时显示定位明确的错误。
- **AC-D09**：给定支持图片的模型，发送的图片能够参与任务；不支持图片的模型须在发送前明确反馈。首版阻止发送，保留输入并提示切换视觉模型。
- **AC-D10**：同一实际工作目录已有任务运行时，不出现第二项并发执行；忙碌时拒绝并保留输入，不自动排队。仅切换查看其他会话不取消原任务。

### REQ-D04：工具、审批与取消

工具过程显示名称、执行状态及结果；命令显示执行内容和输出。需要人工审批的操作在执行前等待，用户可允许或拒绝；桌面接入不能绕过底层权限策略。

- **AC-D11**：触发需审批的操作，决策前不产生相应副作用；拒绝后显示拒绝结果；允许后才执行。审批卡须关联实际会话、轮次与操作。
- **AC-D12**：运行期间点击停止，界面先显示取消请求，只有执行端确认停止后才显示已取消；保留已有消息和改动信息，不误报成功。
- **AC-D13**：审批等待期间取消任务，原审批随后失效；对失效卡片的点击不能让任务恢复执行。
- **AC-D14**：工具失败、模型请求失败或运行异常时，显示可定位的错误，保留已有输出；是否重试由用户新动作触发，不无提示重放有副作用操作。

界面状态契约：

| 状态 | 展示与允许动作 | 转换依据 |
|---|---|---|
| 空闲 | 可编辑并发送 | 用户提交后进入执行 |
| 执行中 | 增量消息、工具状态、停止入口 | 实际事件进入等待审批、完成、失败或取消中 |
| 等待审批 | 具体请求、允许/拒绝、停止入口 | 审批响应或取消 |
| 取消中 | 已请求停止，保留已有输出 | 执行端停止确认后进入已取消 |
| 已完成/失败/取消/中断 | 明确终态和历史，允许发起后续对话 | 新一轮由用户明确触发 |

### REQ-D05：查看和安全撤销本轮改动

展示本轮涉及的文件和逐文件差异，支持打开文件。需区分“本轮改动记录”与“当前工作目录整体差异”，不能把用户已有未提交修改归给 Agent。

撤销先展示影响范围并取得用户确认。执行必须保护本轮开始前已有修改；遇到本轮之后用户继续修改同一内容的情况，不可直接覆盖，须保留内容并提示冲突。首版可拒绝无法安全分离的撤销，不要求自动解决冲突。

- **AC-D15**：任务开始前已有修改 A，本轮产生修改 B，面板能说明本轮范围；撤销 B 后 A 内容保留，已有暂存状态不被无关改变。
- **AC-D16**：本轮后用户在相同位置增加修改 C，尝试撤销出现明确冲突提示；C 不丢失，不使用整目录恢复覆盖它。
- **AC-D17**：给定本轮新增、修改或删除的文件，列表与差异状态与实际结果一致；二进制或不可显示差异时明确提示，不显示空白冒充无变化。
- **AC-D18**：取消撤销确认时文件保持原样；执行失败时说明结果及可能的部分影响，不宣称已全部恢复。

### REQ-D06：模型与配置

模型选择器仅列出当前项目有效配置的提供方所对应的已配置模型，不展示内置推荐目录或未配置项。未显式配置 Ollama 时不默认展示本地模型；设置页保留所有提供方的配置入口。无可选模型时引导进入设置，历史会话的模型已不可选时要求重新选择，不能显示另一模型却仍发送旧模型。

复用已有 Provider 与配置优先级，图形界面支持模型选择、API Key 设置和连接测试。有效配置来源应可解释；环境变量覆盖导致界面保存值未生效时应明确提示。

- **AC-D19**：只有所选 Provider 的有效配置时能启动对应任务，不因缺少无关 DeepSeek Key 而阻断。
- **AC-D20**：配置合法且服务可达时，连接测试显示成功；认证失败、网络失败分别显示可处理的原因，不泄露密钥。
- **AC-D21**：当前轮次采用的 Provider/模型在记录中可查；切换模型不改变已经执行中的请求。模型按会话保存，从下一轮开始生效；历史图片按原有引擎策略裁剪。
- **AC-D22**：凭据不出现在消息、工具输出、错误信息或普通日志中；密钥存于现有全局配置，接口不返回密钥值；输入留空保留原值，首版不提供删除凭据按钮。

### REQ-D07：外部终端

- **AC-D23**：从当前项目打开外部终端，工作目录指向该项目；启动失败时提示原因。首版面板中的命令输出不提供交互式 Shell 输入。

## 6. 页面与状态清单

以下状态按 MVP 核心流程验证，不代表复现 Codex 全部页面。

| 界面 | 空/加载状态 | 错误状态 | 长内容与边界 |
|---|---|---|---|
| 项目与会话侧栏 | 无项目时提供添加入口；加载中可识别 | 目录不可用、历史读取失败 | 长名称和大量会话不遮挡关键操作 |
| 新会话与输入区 | 无消息时可选择项目、模型并输入 | 文件不存在、图片不可用、发送失败 | 多行文字、长路径、多附件不挤出发送/停止入口 |
| 聊天时间线 | 生成中显示实际进展 | 中断、失败、取消分别可辨 | 长代码和工具输出可阅读，切换会话不串流 |
| 工具与审批 | 工具运行、审批等待 | 拒绝、审批失效、执行失败 | 长命令可查看完整内容，不能只靠截断摘要决定审批 |
| 改动面板 | 无变更有明确提示；加载 diff 有反馈 | 文件失效、撤销冲突或失败 | 大文件、长行、二进制均有明确呈现方式 |
| 模型设置 | 未配置可引导；测试中显示状态 | 配置无效、认证失败、服务不可达 | 长模型名/地址不遮挡状态；凭据保持遮蔽 |

## 7. 约束与验证方法

- 平台：首版在 macOS 26.6.2 / Apple Silicon 实测；提供源码启动和本机未签名 `.app` 构建。仍需已安装 Java 21；未承诺 Intel、其他系统及干净机器分发。
- 兼容：保留 CLI 能力和现有配置读取语义，不将桌面新增行为写成已有能力。
- 并发：同一实际工作目录串行，不能用不同项目别名绕过；其他目录的资源并发上限由后续设计确定。
- 生命周期：关闭窗口仅隐藏；菜单退出取消任务并清理后端，异常终止重开标记中断，不自动重放。
- 隐私：产品不新增用户行为遥测；必要本地诊断不记录凭据。
- 功能验收：本次使用本地可控模型，通过真实 Java Provider/Agent/工具链验证；真实收费模型质量与账户连通性留给人工验收，不以离线结果冒充。
- 视觉验收：固定安装版参考及显示条件，覆盖第 6 节的关键状态，不用任意相似度数字冒充“一致”。

## 9. 本次已采用的交互决定

以下选择承接用户“先做 MVP、重点 UI 适配”的实施授权，未增加新的业务能力。

| 事项 | MVP 规则 |
|---|---|
| 视觉基准 | 用户本次提供的主聊天和设置两张浅色截图；设计约定见根目录 DESIGN.md |
| 同目录忙碌 | 按真实目录互斥，阻止第二轮执行并保留草稿，不自动排队 |
| 窗口生命周期 | 关闭窗口隐藏，菜单退出取消任务；异常结束保留已保存部分，不自动重跑 |
| 模型 | 每会话保存，下一轮切换生效；新会话沿用所选 Provider 的配置模型 |
| 附件 | 单轮最多 8 个；文本 256 KB、图片 10 MB 上限；仅显式选择的图片构造成图片消息，文本内 `@image` / `@clipboard` 不触发读取 |
| 图片历史 | 图片复制到桌面私有目录，消息显示附件文件名；模型历史沿用引擎的图片裁剪策略。无图片缩略图浏览器 |
| 会话管理 | 新建、切换、重命名、置顶、归档/恢复、标题搜索 |
| 撤销 | 原生确认；先检查全部受影响文件，再恢复；后续编辑或链接冲突拒绝；中途 I/O 失败说明已恢复数量并保留备份 |
| 分发 | Electron 私有 stdio 调用 Java 核心；源码启动及本机 `.app`，不增加登录、遥测、自动更新和云端能力 |
