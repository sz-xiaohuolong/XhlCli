# Phase 04：安全与审批 PRD

> 优先级：P0
> 状态：已规划
> 前置阶段：Phase 03
> 对应里程碑：M1 可用 Coding Agent

## 1. 阶段目标

建立独立于 Agent 决策的安全与人工审批层。任何工具调用在执行前都必须经过风险分类、路径与命令硬策略、审批策略和审计记录，使用户能够在保持开发效率的同时控制文件写入和命令执行风险。

## 2. 安全模型

```text
模型提出工具调用
  → 参数校验
  → 系统硬策略检查
  → 风险与审批策略判断
  → 必要时请求用户决定
  → 工具执行
  → 脱敏审计
```

系统硬策略优先于用户批准。用户可以允许受支持的操作，但不能批准路径逃逸、已知凭据泄露或系统明确禁止的行为。

## 3. 用户故事

- 作为用户，我希望读取代码时尽量少被打断，但写入和命令执行前得到清晰提示。
- 作为用户，我希望能批准一次、拒绝、修改参数或在有限范围内本次会话放行。
- 作为用户，我希望查看 Agent 执行过哪些高风险操作，同时日志不暴露密钥。
- 作为维护者，我希望新增工具默认受到保护，而不是因漏配直接获得权限。

## 4. 本期范围

- 工具风险元数据与默认拒绝原则。
- 项目根路径围栏和符号链接逃逸检查。
- 命令快速拒绝、风险识别和作用域控制。
- 终端 HITL 审批交互。
- 会话级临时授权，不做永久全局放行。
- JSONL 操作审计与敏感参数脱敏。
- YOLO 模式的受限定义：减少可审批操作的交互，不绕过硬策略。

## 5. 风险分级

| 等级 | 示例 | 默认行为 |
|---|---|---|
| 只读 | 目录、文件、搜索、Git diff | 自动允许并审计摘要 |
| 中风险 | 新建或修改项目内文件 | 请求批准，可按工具或文件范围临时放行 |
| 高风险 | 执行命令、删除、恢复快照、外部写操作 | 每次批准或精确规则放行 |
| 禁止 | 项目外写入、凭据外传、破坏性系统命令 | 直接拒绝，不可批准 |

## 6. 功能需求

### FR-04-01 默认保护

未声明风险等级的新工具按高风险处理。权限配置错误时采取更保守行为。

### FR-04-02 路径围栏

所有文件系统参数在执行前解析为规范路径，并检查绝对路径、`..`、符号链接和目标父目录。项目根之外的写入始终拒绝。

### FR-04-03 命令策略

命令策略至少识别递归删除、磁盘与权限修改、强制 Git 操作、包发布、网络上传、进程管理和可能包含凭据的参数。命令黑名单仅为辅助，不能替代工作目录和权限隔离。

### FR-04-04 审批信息

审批提示展示工具名称、风险等级、目标文件或工作目录、命令摘要、预期影响和拒绝后的处理方式。敏感字段必须掩码。

### FR-04-05 审批决策

支持：批准一次、拒绝、跳过当前步骤、修改可编辑参数后再执行、在当前 Run 的明确范围内放行。取消审批等同拒绝。

### FR-04-06 授权作用域

临时授权必须绑定 Run、工具及必要的路径或命令范围。Run 结束、模式切换或权限上下文变化后自动失效。

### FR-04-07 审计记录

审计至少记录时间、Run ID、工具、风险、参数摘要、策略结果、用户决定、执行结果和耗时。日志写入失败不能静默放行高风险操作。

### FR-04-08 凭据脱敏

对 Key、token、password、secret、Authorization、Bearer、Cookie 等名称和值模式进行脱敏。原始凭据不得进入终端审批文案和审计文件。

### FR-04-09 非交互模式

无终端审批能力时，只读操作可按策略执行；所有需要用户批准的操作默认拒绝，除非存在预先配置的精确规则。

### FR-04-10 策略可解释性

拒绝结果必须包含规则类型和可行替代方案，例如缩小路径、改用只读命令或由用户手工执行。

## 7. 非目标

- 本期不提供容器、虚拟机或操作系统级沙箱。
- 不承诺识别任意 Shell 组合中的所有危险语义。
- 不允许用 YOLO 模式绕过系统硬策略。
- 不存储永久“允许所有命令”规则。
- 不审计文件的完整敏感内容，只记录必要摘要。

## 8. 异常与边界场景

- 审批期间收到 Ctrl+C 时拒绝当前操作并取消或返回 Agent。
- 用户修改参数后必须重新执行参数校验和硬策略检查。
- 同一工具参数变化后不得复用旧批准。
- 审计目录不可写时，高风险工具拒绝执行并提示修复方式。
- 命令使用 Shell 管道、重定向或子命令时按完整文本提高风险，不能只检查首个单词。
- 大小写或编码变形的敏感字段仍应尽可能脱敏。

## 9. 体验要求

- 审批提示使用简短语言，默认聚焦影响，不展示大段 JSON。
- 用户可以展开查看完整非敏感参数。
- 拒绝后 Agent 获得结构化 Observation，可以提出更安全方案。
- 状态区明确显示当前是普通审批模式还是受限 YOLO 模式。

## 10. 验收标准

1. 项目根外写入、符号链接逃逸和明确禁止命令均不可通过用户批准执行。
2. 只读工具默认不打断；写入和高风险命令按策略请求批准。
3. 批准一次不会扩展为其他工具、其他路径或后续 Run 的授权。
4. 修改参数后会重新执行全部检查。
5. 审计日志可以还原决策时间线，但不出现测试用真实凭据。
6. 非交互模式下所有待审批操作默认拒绝。
7. 新增未标风险工具会以高风险处理。

## 11. 测试与验证

- 决策表测试：工具类型 × 风险 × 模式 × 用户选择。
- 路径测试：相对路径、绝对路径、`..`、软链接、尚不存在的目标。
- 命令测试：安全构建、递归删除、强制 Git、管道重定向和环境变量。
- 脱敏测试：常见字段名、Bearer、URL 参数和嵌套 JSON。
- 手工演示：批准文件修改、拒绝危险命令、查看脱敏审计。

## 12. GitHub 交付物

- 安全模型和审批决策表。
- 威胁边界说明，明确“策略层不等于沙箱”。
- 恶意参数与路径逃逸回归测试。
- 审计日志脱敏示例。

## 13. 下一阶段接口

后续所有内置工具、MCP 工具、浏览器写操作、快照恢复和后台任务都必须接入同一权限入口，不得各自实现旁路审批。
