## 1. 产品概述与背景

- **背景与痛点：** 在 [`desktop-codex-ui.md`](desktop-codex-ui.md) 已交付的桌面端能力中，`PlanReview` 仅提供“整份计划预览 + 单一全局意见输入框”，用户在审阅多步骤 DAG 计划时，需要自行在文本框中描述“哪一步的哪句话要改/要删”；同时，`diff-panel` 仅支持只读查看本轮文件差异和整体撤销，用户发现某几行代码有问题时，无法直接在 Diff 行上添加评论并回发给 Agent 修正。
- **产品定位：** 为现有 Electron 桌面 UI 补齐“结构化批注与回发”闭环，覆盖 **Plan 划线批注** 与 **Diff 行内评论回发** 两项能力，全程在现有桌面界面内完成，无需用户在本地额外安装或配置 `plannotator` 外部二进制。
- **成功定义：**
  1. 用户可在聊天流 `PlanReview` 卡片或展开的双栏精审视图中，通过划词、红线删除或步骤快捷操作为计划添加批注，并自主选择 **按批注更新计划** 或 **同意执行并附带备注**；
  2. 用户可在代码变更审阅面板查看真实新旧行号，单选或多选（`Shift` 连选 / 拖拽）代码行添加评论，并将汇总反馈一键填入底部输入框聚焦或直接发起新一轮对话任务；
  3. 延续现有 `DESIGN.md` 浅色工作台视觉规范、人工审批边界和本地数据隔离要求。

## 2. 目标与非目标

### 核心目标

- **目标 G-01（Plan 精确审阅与备注执行）：** 降低用户在长计划审批中定位具体语句和步骤的表达成本，并允许在不强制重规划的前提下携带约束备注直接放行执行。
- **目标 G-02（Diff 行级评审闭环）：** 打通“查看本轮文件变动 → 行内指出问题/修改意见 → 回发给 Agent 继续修复”的代码审查闭环，支持多行区间引用与草稿暂存。
- **目标 G-03（零外部依赖融入）：** 直接增强现有 Electron 桌面前端与 Java 本地执行层，不要求用户安装 Bun、`plannotator` 等第三方 CLI，保持现有项目与会话历史向后兼容。

### 范围与非目标

- **本次覆盖：**
  - 现有 Electron 桌面端（`desktop/src/`）的 `PlanReview` 交互增强（内联划词批注/红线删除 + 可选宽屏双栏精审视图）及对应的 `PlanExecuteAgent` / `DesktopService` 最小后端适配（支持 `execute` 携带执行备注与合理放宽结构化反馈长度限制）。
  - 现有 Electron 桌面端（`desktop/src/`）右侧代码变更面板（`diff-panel`）升级：Unified Diff 真实双行号展示、单行与多行选区评论、标准/加宽/全屏宽度切换、未提交草稿本地缓存、汇总填入输入框及直接发送。
- **明确不做（非目标）：**
  - **不做计划版本对比（Plan Diff）：** 用户在 2026-11-17 需求对齐中未勾选“多轮重规划后的计划版本对比（Plan Diff）”，本次不实现跨版本步骤高亮对比，留作后续候选。
  - **不绑定外部 `plannotator` 进程 / MCP Inbox / 团队分享链接：** 不启动外置 Bun/HTTP 服务，不上传 Diff 或 Plan 到任何远程链接。
  - **不做纯终端 CLI 的内置 Web 审阅服务：** 本次聚焦现有 Electron 桌面 UI；纯 CLI 模式仍保持现有终端交互（后续如有需要另行立项）。
  - **不改变既有人工审批底线：** 工具硬权限策略、`plan_review` 独立确认以及“帮我审批”不自动放行计划的边界保持不变（沿用 [`desktop-codex-ui.md`](desktop-codex-ui.md) AC-PLAN-01）。

## 3. 目标用户与使用场景

| 用户角色 | 角色特征与权限范围 | 核心诉求 | 典型触发场景与预期结果 |
|---|---|---|---|
| macOS 本地编程开发者 | 在桌面客户端管理本地代码目录、运行 `/plan` 规划并审阅 Agent 产出的代码改动 | 更快指出计划里具体哪句话或哪一步需要改/删；看 Diff 时直接在有问题代码行写意见并让 Agent 按意见接着改 | 在桌面会话中发起 `/plan` 或普通改代码任务后，分别通过划词/点击行号精准批注，最终把结构化反馈发给 Agent 重新规划或继续修复 |

**场景概要：**
1. 用户发送 `/plan <目标>`，进入 `plan_review` 状态；用户在 `PlanReview` 卡片里选中某步骤的一句话点击“添加批注”或“红线删除”，或点击“展开精审”在宽屏双栏界面中集中浏览并整理批注，之后选择“按批注更新计划”触发重规划，或选择“同意执行（含备注）”让每个执行步骤收到备注约束并直接运行。
2. 某轮任务产生文件变更后，用户点击“查看变更”打开右侧 Diff 面板，按需切换为加宽或全屏视图；阅读带真实新旧行号的代码变化，点击单行或 `Shift`/拖拽连选多行输入批注；完成后点击“汇总填入输入框”在输入框确认或补充一句话后发送给 Agent 修复，或点击“直接发送”立即启动下一轮执行。

## 5. 核心功能详细规格与验收标准

### 5.1 `REQ-PDA01`：Plan 内联划词批注与双栏精审

**来源与前提**

- **需求来源：** 用户原始请求及 2026-11-17 问答 Q1 确认。
- **使用者与入口：** 会话中执行 `/plan` 后处于 `plan_review` 状态的桌面用户，入口为聊天时间线内当前活跃的 `PlanReview` 卡片及其右上角「展开精审」按钮。
- **前置条件：** 存在未解决的活跃 `plan.ready`（`turn.status === 'plan_review'` 且该计划 ID 未被 `plan.resolved`）。
- **完成结果：** 用户可通过选区划词或步骤快捷入口创建、查看、编辑和删除 `COMMENT`（批注）、`DELETION`（红线删除建议）及全局意见，且内联卡片与双栏视图共享同一份实时批注列表。

**正常流程**

1. 用户在活跃 `PlanReview` 的计划目标、摘要或步骤文本中用鼠标选中一段文字，文本附近出现浅色操作浮条（包含「添加批注」「红线删除」）；或在任意步骤右侧点击快捷「批注」按钮，自动以该步骤完整描述或首句摘要作为锚点弹出输入框。
2. 用户输入批注说明并保存（`DELETION` 可选留空，表示直接建议删去该片段），系统生成一条带锚点（类型、目标区域/步骤编号、原文引用 `originalText`、批注内容）的记录。
3. 计划渲染区对应引用片段呈现视觉标记（`COMMENT` 柔和琥珀/浅蓝标亮，`DELETION` 红色删除线），点击标记或批注清单条目可查看、修改或移除该条批注。
4. 若计划较长，用户点击「展开精审」，打开宽屏双栏浮层（左侧完整展示计划内容与标亮/删除线，右侧集中列出全部批注条目的管理栏及全局意见输入区、操作按钮）；关闭精审返回聊天流后，所有未提交的批注与输入保持同步。

**业务规则与权限**

| 规则 | 明确约定 | 适用边界 |
|---|---|---|
| 批注类型 | 支持三种类型：`COMMENT`（划词或步骤批注，要求文本非空）、`DELETION`（红线删除建议，可附带替换或说明，允许只标记删除原文）、`GLOBAL_COMMENT`（底部全局意见文本框）。 | 仅对当前活跃且未决议的 `PlanReview` 允许新增/修改/删除批注。 |
| 原文锚点匹配与降级 | 划词批注保留精确引用文本及所属块归属（目标/摘要/步骤序号）；若同一段文本在同一区域重复出现或因渲染差异无法精确高亮，卡片中仍须完整保留并展示在批注清单中，不得静默丢失。 | 不支持跨 `PlanReview` 卡片外区域（例如普通助手消息）的划词混入计划批注。 |
| 历史计划状态 | 已解决或已失效/中断的计划仅保留历史只读状态，不提供新增/修改批注按钮或执行按钮。 | 承接现有 `AC-PLAN-02` 的幂等与失效约束。 |

**异常与边界**

| 条件或触发事件 | 对用户的反馈 | 最终状态与后续动作 |
|---|---|---|
| 划词跨出 `PlanReview` 内容边界或选区纯为空白 | 不弹出批注浮条。 | 原批注列表不受影响。 |
| 用户处于正在提交决策状态（`sending`） | 禁用新增、删除批注与按钮重复点击，防止中途状态不一致。 | 请求返回成功则清空草稿进入新状态；失败则恢复编辑能力并显示错误。 |

**验收标准与检查入口**

| 验收编号 | 可判定场景 | 输入与观察入口 |
|---|---|---|
| `AC-PDA01` | **给定** 一条处于 `plan_review` 状态的计划含多条步骤，**当** 用户在步骤或摘要内选中非空文本并创建 `COMMENT` 与 `DELETION` 批注，或通过步骤快捷按钮创建批注，**则** 批注清单正确显示对应引用原文、步骤定位与类型标记，且内联视图呈现对应高亮/红线视觉样式并支持删除。 | 触发：桌面 UI / React 渲染与 DOM 事件测试；观察：`PlanReview` 组件输出与状态同步。 |
| `AC-PDA02` | **给定** 当前活跃计划已添加若干条批注及全局意见，**当** 用户点击「展开精审」进入双栏视图并新增/修改批注后收起精审视图，**则** 双栏与聊天内联卡片显示完全一致的批注列表与全局输入，且可通过 Escape 或关闭按钮安全退出而不丢失草稿。 | 触发：桌面 UI 点击展开/关闭操作；观察：内联卡片与双栏列表的一致性。 |

### 5.2 `REQ-PDA02`：Plan 批注驱动重规划与带备注执行

**来源与前提**

- **需求来源：** 用户 2026-11-17 问答 Q2 确认。
- **使用者与入口：** 桌面 UI 活跃 `PlanReview` 底部及双栏精审侧栏操作按钮区（「按批注更新计划」/「更新计划」、「同意并执行」/「同意执行（含备注）」、「取消计划」）。
- **前置条件：** 同 `REQ-PDA01`；且后端 `DesktopService.respondToPlan` 与 `PlanExecuteAgent` 处于等待本次 `planId` 决策的状态。
- **完成结果：** 根据用户所选动作，结构化格式化后的批注与备注被可靠持久化并驱动重规划或直接注入任务执行上下文。

**正常流程**

1. **按批注更新计划（`supplement`）：** 当存在至少一条行内/红线批注或全局意见非空时，用户点击「更新计划」，前端调用通用格式化器将所有 `COMMENT`、`DELETION` 与全局意见整理为结构化 Markdown 反馈（含步骤序号及引用原文），作为 `feedback` 通过 `plan.respond` 发送。Java 后端校验通过后持久化 `plan.resolved` 事件并触发 `Planner` 重新生成新版计划。
2. **同意执行（含/不含备注，`execute`）：**
   - 若没有任何行内批注与全局备注，按钮显示为「同意并执行」，提交 `action: "execute"`，行为与既有逻辑一致；
   - 若存在任意行内批注或全局备注，主按钮清晰提示为「同意执行（含备注）」（或附带提示），点击后将同一套结构化 Markdown 备注作为 `feedback` 随 `action: "execute"` 发送。Java 后端不触发重规划，而是将备注写入本次 `ExecutionPlan` 并附带在每一步任务执行提示上下文中，同时在 `plan.resolved` 事件里持久化该备注。
3. **历史状态回溯：** 计划提交后卡片折叠，历史摘要明确区分 `你已同意执行`、`你已同意执行（含备注）`、`已提交修改意见`、`已取消计划`，展开详情仍可查看当时记录。

**业务规则与权限**

| 规则 | 明确约定 | 适用边界 |
|---|---|---|
| 结构化输出格式 | 依次包含全局意见（如有）、行内批注（标注所属步骤/区域 + 原文引用 + 意见正文）与红线删除建议（标注原文引用 + 说明/删改意图）。 | 单条 `COMMENT` 与 `DELETION`、仅全局意见、三者混合均生成人类与模型可读的结构化文本。 |
| 备注长度上限 | 将 `DesktopService.respondToPlan` 对 `feedback` 的长度校验放宽至合理支持多条批注的上限（例如 `32000` 字符），前端提交前若仍超限先给出明确中文提示而不崩溃。 | 仅允许在 `supplement` 必填非空；`execute` 时 `feedback` 为可选（空字符串视同无备注）。 |
| 重规划与直接执行的语义隔离 | `supplement` 必触发 `Planner` 重新生成并再次进入 `plan_review`；`execute`（含备注）绝不触发重新规划，而是直接进入任务执行并将备注传递至任务上下文。 | 若审批决定持久化失败（如磁盘异常），保持当前确认态，不得放行执行任务。 |

**异常与边界**

| 条件或触发事件 | 对用户的反馈 | 最终状态与后续动作 |
|---|---|---|
| 在无任何行内批注、红线且全局意见为空时点击「更新计划」 | 按钮禁用不可点击。 | 保持 `plan_review` 等待态。 |
| 计划已超时/被取消/已被重开覆盖后前端延迟提交 `plan.respond` | 后端拒绝并返回中文提示（计划确认已失效）。 | 不触发规划或执行。 |

**验收标准与检查入口**

| 验收编号 | 可判定场景 | 输入与观察入口 |
|---|---|---|
| `AC-PDA03` | **给定** 计划中有 2 条划词/红线批注和 1 段全局意见，**当** 点击「更新计划」，**则** `plan.respond` 收到 `action="supplement"` 及包含步骤编号/引用原文的结构化 `feedback`，模型基于该结构化要求重新生成计划并进入下一次 `plan_review`。 | 触发：`DesktopService` + `PlanExecuteAgent` 集成测试与前端格式化单测；观察：`plan.resolved` 事件与新计划输入参数。 |
| `AC-PDA04` | **给定** 计划有批注或备注时用户点击「同意执行（含备注）」，**当** `plan.respond` 携带 `action="execute"` 与非空 `feedback` 到达后端，**则** 系统不调用 `planner.createPlan` 重规划，而是直接执行原计划，且 `executeTask` 发送给模型的上下文包含该备注，同时历史记录显示含备注状态。 | 触发：Java `PlanExecuteAgentTest`、`DesktopServiceTest` 与前端 `conversation.test.cjs`；观察：模拟模型收到的 prompt 与事件日志。 |
| `AC-PDA05` | **给定** 结构化反馈长度在原 `8000` 字符以上且不超过新上限（如 `16000` 字符），**当** 提交 `supplement` 或 `execute` 备注，**则** 后端正常接纳并持久化处理；超过上限时后端与前端均返回清晰的中文字符数提示而不抛出未捕获异常。 | 触发：`DesktopService` 单元测试。 |

### 5.3 `REQ-PDA03`：Diff 真实行号解析与单/多行评论回发

**来源与前提**

- **需求来源：** 用户原始请求及 2026-11-17 问答 Q3、Q4 确认。
- **使用者与入口：** 用户在完成有文件改动的轮次卡片上点击「查看变更」打开右侧 `diff-panel`。
- **前置条件：** 对应轮次存在 `before` / `after` 快照且 `DesktopChanges.diff` 返回至少一个文件（或空变更明确提示）。
- **完成结果：** 代码行按真实新旧行号展示，用户可通过点选或 `Shift`/拖拽连选加行内评论，并一键汇总回发给 Agent 修正。

**正常流程**

1. **解析展示行号：** 前端 Unified Diff 解析器从每个 `@@ -oldStart,oldCount +newStart,newCount @@` 块头起逐行计算 `oldLine`（删除行与上下文行递增）与 `newLine`（新增行与上下文行递增），渲染为行号双槽 + 代码内容，保留 `+`/`-`/`hunk` 语义配色与二进制/截断提示。
2. **单行与多行选区评论：**
   - 用户点击某代码行触发选中（进入待写评论行内表单）；按住 `Shift` 点击同文件同一 Diff 区块内的另一行，或按下鼠标连续拖选，可将选区扩展为多行区间（如 `L42–L48`）；
   - 在行下方内嵌展开的轻评论框中输入意见并保存，该代码区间下立即内联渲染一条评论卡片，并同步计入面板顶部/底部的待回发评论总数。
3. **汇总与回发：**
   - 面板底部提供可选的「总评/补充说明」输入框与两个回发操作：
     - **「汇总填入输入框」**（主操作）：调用格式化器将所有文件的行内评论（精确路径、新/旧行号区间、引用代码片段与意见正文）及可选总评整理为干净 Markdown，写入当前会话底部聊天输入框并立即聚焦，随后收起（或保留用户按需手动关闭，不强行丢失面板数据直到发送或手动清理——详见规则说明）以便用户继续补充一句提示后按 Enter 发送；
     - **「直接发送给 Agent」**（次操作）：当当前项目目录空闲时可用，直接调用 `turn.start` 将同一份结构化 Markdown 作为新任务发送给 Agent 执行，清除本轮 Diff 草稿并自动关闭 Diff 面板。

**业务规则与权限**

| 规则 | 明确约定 | 适用边界 |
|---|---|---|
| 行号锚定规则 | 对新增行/上下文行优先输出新文件行号（如 `L42` 或 `L42-L46`）；对纯粹删除行标注原文件行号及 `(已删除行)` 标识（如 `old L18 (已删除)`），并在反馈中附上最多数行精简引用代码以防行号漂移。 | 仅在同一文件的 Diff 行内支持连选区间；跨文件选区不合并为单条评论。 |
| 不可评论的行 | 文件头信息（`diff --git`、`---`、`+++`、`@@` hunk 标识行）、`\ No newline at end of file`、截断警告及二进制文件提示行不可作为代码行号选中评论。 | 二进制或过长被截断文件仍支持通过底部总评进行文字说明。 |
| 忙碌互斥保护 | 当同一真实工作目录已有任务正在运行（`directoryBusy === true`）时，禁用「直接发送给 Agent」，但仍允许正常浏览 Diff、写行内评论及「汇总填入输入框」（存入当前聊天框草稿）。 | 沿用 `AC-D10` 目录并发互斥约束。 |
| 回发文本追加策略 | 点击「汇总填入输入框」时，若当前输入框已有未发送文字，则在其末尾追加两空行再拼入汇总评论（不静默覆盖用户已手写的文字）。 | 若写入内容与当前输入框完全一致则不重复追加。 |

**异常与边界**

| 条件或触发事件 | 对用户的反馈 | 最终状态与后续动作 |
|---|---|---|
| 待发送行内评论为 0 条且底部总评为空 | 「汇总填入输入框」与「直接发送给 Agent」按钮均处于禁用状态，展示明确提示（如“点击或 Shift 连选代码行即可添加批注”）。 | 面板保持只读浏览与撤销能力不受影响。 |
| 本轮变更已执行「撤销本轮」（`turn.undone === true`） | 顶部与操作区明确标示本轮改动已撤销；仍可查看记录与复制引用，默认禁用「直接发送给 Agent」（避免让 Agent 对已撤销改动盲改，除非用户通过「汇总填入输入框」自行修改后再发）。 | 文件与快照状态保持不变。 |
| JGit diff 为二进制提示或无标准 `@@` hunk | 解析器安全退化展示原始摘要行，不抛 JS 异常导致整块聊天白屏。 | 正常展示文件状态和撤销功能。 |

**验收标准与检查入口**

| 验收编号 | 可判定场景 | 输入与观察入口 |
|---|---|---|
| `AC-PDA06` | **给定** 一段包含多 hunk、新增行（`+`）、删除行（`-`）和上下文行（` `）的 JGit unified diff，**当** `parseUnifiedDiff` 解析并渲染，**则** 每一代码行的 `oldLine` 和 `newLine` 与真实行号 100% 匹配，且 `@@` 头部、`\ No newline` 及二进制/截断信息不会错位累计行号。 | 触发：Node 单元测试（`annotations.test.cjs`）；观察：解析结构行号断言。 |

### 5.4 `REQ-PDA04`：Diff 宽度切换与批注草稿持久化

**来源与前提**

- **需求来源：** 用户 2026-11-17 问答 Q4 确认。
- **使用者与入口：** `PlanReview`（桌面聊天流与精审视图）及右侧 `diff-panel` 头部宽度控制区。
- **前置条件：** 桌面前端支持本机 `localStorage`（不可用时静默退化为内存态）。
- **完成结果：** 用户可按代码行长度调节 Diff 面板宽度，且意外关闭面板或切换会话/刷新时未提交的批注草稿得以保留。

**正常流程**

1. **Diff 面板宽度切换：** 面板右上角提供宽度循环/分段切换按钮，支持三档：**标准**（复用现有约 `37%` 右侧并排面板）、**加宽**（约 `62%` 宽面板）及**全屏精审**（覆盖工作区内容区以便双列对照长行 Diff）。用户调整的面板宽度偏好可随会话界面保留。
2. **草稿本地持久化：**
   - 当用户向活跃 `PlanReview` 添加/修改/删除批注或输入全局意见时，实时按 `plan:<sessionId>:<planId>` 为键自动存入 `localStorage`；
   - 当用户在 `diff-panel` 写下代码行评论或总评时，按 `diff:<sessionId>:<turnId>` 为键实时存入 `localStorage`；
   - 当 Plan 决策提交成功（`plan.respond` 成功返回）或 Diff 评论通过「直接发送」提交成功后，自动清除对应草稿键；点击「汇总填入输入框」时可选保留或提供一个显式「清空评论」操作，避免用户尚未真正发送前就丢失源评论记录（当用户手写清理或点「清空」按钮时移除）。

**业务规则与权限**

| 规则 | 明确约定 | 适用边界 |
|---|---|---|
| 草稿清理与安全降级 | `localStorage` 读取遇到 JSON 损坏或写入配额超限异常时，静默回退为当前内存态，严禁中断审批/发送主流程。 | 不将任何后端 API Key 或工作区外部路径写入浏览器草稿存储；草稿只保存批注文本与界面锚点引用。 |
| 窄屏响应式退化 | 当窗口宽度较窄（沿用现有 `@media(max-width:1150px)` 断点）时，标准与加宽模式自动以覆盖层展示且不超出可视宽度，避免按钮被挤出屏幕。 | 与 `DESIGN.md` 窄窗口适配一致。 |

**验收标准与检查入口**

| 验收编号 | 可判定场景 | 输入与观察入口 |
|---|---|---|
| `AC-PDA09` | **给定** 用户在 `PlanReview` 与 `diff-panel` 均录入未提交的批注草稿，**当** 关闭 `diff-panel` 并切换至另一会话后再切回原会话/重新打开面板，**则** 先前录入的 Plan 批注与 Diff 行内评论完整恢复；成功提交 `plan.respond` 或「直接发送」后，对应草稿从本地缓存中清除。 | 触发：Node 单测模拟 Storage + 桌面交互验证；观察：状态恢复与清理结果。 |
| `AC-PDA10` | **给定** Diff 面板处于打开状态，**当** 在「标准 / 加宽 / 全屏」间切换并在窄窗口下检查布局，**则** Diff 面板宽度按档位变化，所有操作按钮（撤销、关闭、宽度切换、汇总填入、直接发送）保持可见且不发生横向遮挡错位。 | 触发：CSS 样式与实际 Electron 桌面截图/交互核验。 |
