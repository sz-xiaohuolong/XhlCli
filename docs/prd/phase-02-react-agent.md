# Phase 02：ReAct Agent PRD

> 优先级：P0
> 状态：已规划
> 前置阶段：Phase 01
> 对应里程碑：M1 可用 Coding Agent

## 1. 阶段目标

在稳定模型对话之上建立 ReAct Agent 执行循环，使模型能够根据任务状态选择结构化工具、接收执行结果并继续决策，直到给出最终答复或触发停止条件。本期使用受控的演示工具验证循环，不开放真实文件写入和命令执行。

## 2. 用户价值

- 用户不再需要手工拆分“先查什么、再做什么”，Agent 可以根据 Observation 自主推进。
- 每一步工具调用和结果都可观察，失败后可以继续调整策略。
- 循环受到次数、时间、取消和重复调用限制，不会无限运行。

## 3. 用户故事

- 作为用户，我希望模型在需要信息时主动调用工具，而不是编造结果。
- 作为用户，我希望知道 Agent 当前调用了哪个工具以及调用是否成功。
- 作为维护者，我希望 Agent 循环可用假的模型与工具进行确定性测试。

## 4. 本期范围

- ReAct 风格的“模型决策—工具执行—结果回灌—继续决策”循环。
- 结构化 Tool 定义、注册、查找、参数解析和结果模型。
- 演示工具：回显、时间或内存键值工具，用于验证协议。
- 一轮返回一个或多个 Tool Call 的兼容消息结构；本期按顺序执行。
- 最大迭代次数、整体超时、用户取消和正常完成条件。
- 重复调用检测和无进展保护。
- 统一运行事件，用于终端显示而不与 Agent 业务耦合。

## 5. 状态模型

一次 Run 至少经历：

```text
created → thinking → calling_tool → observing → thinking
        → completed | failed | canceled | limit_reached
```

`completed` 只表示模型给出不含工具调用的最终答复且消息协议完整。达到迭代上限时应进入 `limit_reached`，并输出已完成事项和未完成原因。

## 6. 功能需求

### FR-02-01 工具声明

每个工具包含唯一名称、面向模型的描述、JSON 参数结构和执行入口。重复名称在启动时失败，不能静默覆盖。

### FR-02-02 工具调用解析

Agent 必须验证工具名称、调用 ID 和参数 JSON。未知工具或非法参数转化为结构化失败 Observation，并允许模型纠正一次，而不是让进程崩溃。

### FR-02-03 Observation 回灌

工具结果必须与原调用 ID 关联，并保持消息顺序。结果包含成功状态、用户可读摘要和供模型判断的结构化信息。

### FR-02-04 迭代控制

默认最大迭代次数由配置提供，并有合理上限。达到限制时停止调用新工具，不把限制状态伪装成正常完成。

### FR-02-05 取消与超时

用户取消或整体超时后，Agent 不再发起新的模型请求或工具调用。当前可取消操作应收到取消信号。

### FR-02-06 无进展保护

当 Agent 连续多次以相同参数调用同一工具并获得相同结果时，应注入提醒或终止运行，避免无意义循环。

### FR-02-07 可观察事件

至少产生运行开始、模型请求、工具开始、工具结束、迭代完成、运行完成、运行失败和取消事件。事件不得包含模型私有思维过程或未脱敏凭据。

### FR-02-08 异常隔离

单个工具抛出异常时转换为失败 Observation；协议或不可恢复状态损坏时终止本次 Run，但保持 CLI 可继续接受新任务。

## 7. 终端体验

- 工具开始时显示名称和安全的参数摘要。
- 工具完成时显示成功、失败、耗时和结果摘要。
- 默认折叠冗长 Observation，调试模式可查看完整结果。
- 达到限制、失败或取消时明确说明状态，不能只结束输出。

## 8. 非目标

- 不实现真实文件系统和 Shell 工具。
- 不实现计划模式、并行工具或 Multi-Agent。
- 不持久化 Run，也不支持崩溃恢复。
- 不依赖模型自然语言中的 `Thought:` 文本来判断状态。

## 9. 异常与边界场景

- 模型同时返回文本和工具调用时，文本作为过程说明保留，工具调用继续执行。
- 工具结果过大时按预算截断，并告知原始大小与继续查询方式。
- 模型返回重复调用 ID 时拒绝该批次并终止协议错误。
- 未注册任何工具时仍可退化为 Phase 01 对话。
- 模型持续返回空响应时按可恢复错误重试有限次数后失败。

## 10. 验收标准

1. 模拟模型可以完成至少三步工具链并给出最终答案。
2. 未知工具、非法 JSON、工具异常和空响应均不会导致 CLI 崩溃。
3. 达到最大迭代、超时或取消后不再出现新的工具执行记录。
4. 相同工具与参数的重复循环能够被检测并停止。
5. 工具结果按调用 ID 和原始顺序回灌。
6. 运行事件足以重建用户可见的执行时间线。

## 11. 测试与验证

- 单元测试：工具注册、参数验证、结果关联、状态迁移和重复检测。
- 场景测试：成功链路、工具失败后纠正、迭代耗尽、取消、协议损坏。
- 性质检查：Run 进入终态后不能再次产生模型或工具事件。
- 手工演示：Agent 通过两个演示工具完成组合任务。
