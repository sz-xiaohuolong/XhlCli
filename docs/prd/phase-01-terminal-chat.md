# Phase 01：终端对话 PRD

> 优先级：P0
> 状态：实施完成，验收中
> 前置阶段：Phase 00
> 对应里程碑：M0 可运行基础

## 1. 阶段目标

提供稳定的终端模型对话能力，完成“配置模型—输入消息—流式查看回答—继续对话—安全退出”的最小体验。本期只建设聊天基础，不允许模型调用本地工具。

## 2. 用户价值

- 用户可以在项目目录中直接与模型持续对话。
- 用户能看到首个输出的实时反馈，而不是等待完整响应。
- 模型配置和错误均以可诊断方式呈现，为后续 Agent 循环提供可靠基础。

## 3. 用户故事

- 作为新用户，我希望通过环境变量配置一个模型并开始对话。
- 作为开发者，我希望回答以流式方式显示，并能使用 Ctrl+C 中断当前响应。
- 作为排障用户，我希望鉴权、限流、网络和配置错误得到不同提示。

## 4. 本期范围

- 单一默认 Provider 的文本模型接入。
- OpenAI-compatible Chat Completions 风格的基础消息和流式响应。
- 会话内多轮消息历史。
- `/help`、`/clear`、`/config`、`/exit` 基础命令。
- API Key、模型名、Base URL、超时和日志级别配置。
- 请求取消、超时、重试边界和错误分类。
- Token 使用量在 Provider 返回时展示；缺失时明确标记未知。

## 5. 核心流程

```text
启动 XhlCLI
  → 检查项目与模型配置
  → 显示当前模型和输入提示
  → 用户输入问题
  → 发送消息历史
  → 流式展示回答
  → 保存本次会话内历史
  → 等待下一次输入
```

## 6. 功能需求

### FR-01-01 配置加载

配置按“命令行参数 > 环境变量 > 本地配置文件 > 默认值”合并。启动时展示 Provider 和模型名，但不得显示 API Key。

### FR-01-02 流式对话

模型文本到达后应增量输出。首个文本片段出现前显示非阻塞等待状态；响应完成后恢复输入提示。

### FR-01-03 多轮历史

当前进程内保留 `system/user/assistant` 消息顺序。`/clear` 清除当前对话但不删除用户配置。

### FR-01-04 中断与退出

响应生成期间第一次 Ctrl+C 取消当前请求并回到输入；空闲状态下退出需走统一清理流程。不得因取消留下无法继续输入的终端状态。

### FR-01-05 错误分类

至少区分缺少配置、鉴权失败、请求限流、网络不可达、服务端错误、响应格式错误、超时和用户取消。用户提示包含可执行的处理建议。

### FR-01-06 日志与脱敏

普通模式只展示必要错误；调试模式可以记录请求元数据和事件，但必须脱敏 Authorization、API Key 和可能的凭据参数。

### FR-01-07 基础命令

- `/help`：显示命令说明。
- `/config`：显示当前非敏感配置及配置来源。
- `/clear`：清空会话历史并给出确认。
- `/exit`：安全退出。

## 7. 非目标

- 不提供工具调用、文件修改和命令执行。
- 不提供多 Provider 运行时切换。
- 不持久化完整会话历史。
- 不实现 Markdown 复杂渲染或全屏 TUI。
- 不展示或保存模型私有思维过程。

## 8. 异常与边界场景

- 用户提交空白输入时不发送请求。
- 响应中途断流时保留已经显示的文本，并标记响应未完整结束。
- 模型返回未知事件类型时记录调试信息并安全忽略，不能导致会话崩溃。
- 历史包含非法消息顺序时拒绝发送并提示内部一致性错误。
- Base URL 非法时在首个网络请求前失败。

## 9. 非功能要求

- 首个流式片段到达后 100 毫秒内显示。
- 所有 HTTP 调用具备连接、读取和整体请求超时。
- 模型客户端可用测试替身替换，CLI 测试不依赖真实 API。
- Windows、macOS、Linux 基础输入和 Ctrl+C 行为均有验证记录。

## 10. 验收标准

1. 配置有效时可以连续完成至少 5 轮流式对话。
2. `/clear` 后下一次请求不携带清理前的用户和助手消息。
3. 响应中按 Ctrl+C 可以取消请求并继续输入。
4. 缺少 Key、错误 Key、超时和 429 均显示不同错误与建议。
5. 调试日志和终端输出中不出现完整 API Key。
6. 模拟流式、断流、超时和取消的自动测试通过。

## 11. 测试与验证

- 单元测试：配置优先级、消息序列、SSE 事件解析、错误映射、脱敏。
- 集成测试：Mock HTTP Server 返回正常流、错误码、延迟和中断流。
- 手工验证：真实 Provider 完成多轮问答与 Ctrl+C 取消。
- 回归检查：`--help`、`--version` 仍保持 Phase 00 行为。
