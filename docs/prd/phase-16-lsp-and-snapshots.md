# Phase 16：诊断与快照 PRD

> 优先级：P2
> 状态：已规划
> 前置阶段：Phase 03、04、15
> 对应里程碑：M4 工程化发行

## 1. 阶段目标

为文件修改增加快速诊断反馈和独立可恢复快照。Agent 在编辑后能获得语法或语言服务诊断，并在任务失败或用户不满意时恢复到本轮修改前，而不依赖用户项目已有 Git 提交历史。

## 2. 用户价值

- Agent 修改代码后能立即发现明显语法和类型问题。
- 用户可以查看每轮修改前后状态并安全恢复。
- 快照不会污染用户分支、暂存区和提交历史。

## 3. 子能力 A：诊断

### 本期范围

- 统一诊断模型：severity、文件、行列、message、source、code。
- 文件修改后的非阻塞诊断。
- Java 轻量语法诊断作为最低能力。
- 一个外部 LSP stdio JSON-RPC 适配器的实验支持。
- 诊断预算、去重、展示和下一轮 Agent 注入。

### 功能需求

#### FR-16-01 触发时机

成功写入受支持文件后触发诊断。诊断失败不把已成功的文件写入改判为失败，但必须显示降级状态。

#### FR-16-02 结果注入

错误优先于警告和信息，按文件与位置排序，默认限制条数。诊断进入下一次模型决策前，Agent 可以据此修复。

#### FR-16-03 防抖与版本

连续修改同一文件时只保留最新内容版本的诊断。迟到结果不得覆盖新版本状态。

#### FR-16-04 LSP 生命周期

外部 Language Server 的启动、初始化、文件同步、超时、退出和重启状态可观察。未安装时自动降级，不阻塞 Agent。

## 4. 子能力 B：Side-History 快照

### 本期范围

- Run 或 Turn 修改前 `pre` 快照、结束后 `post` 快照。
- 快照存储在用户目录的隔离位置，不写项目 `.git`。
- `/snapshot`、`/snapshot status`、`/restore <id>` 和清理策略。
- 恢复前创建保护快照。
- 忽略构建产物、依赖目录和敏感大文件。

### 功能需求

#### FR-16-05 快照隔离

快照按项目真实路径和工作树标识隔离，不修改用户当前分支、HEAD、索引或提交历史。

#### FR-16-06 快照时机

首次写操作前确保存在修改前快照；Run 结束后异步记录结果快照。只读任务不强制创建内容快照。

#### FR-16-07 恢复预览

恢复前展示目标快照、时间、来源 Run 和将变化的文件。恢复属于高风险操作，必须经过审批。

#### FR-16-08 用户改动保护

如果当前文件自目标快照后包含无法归属本 Run 的修改，恢复前明确提示冲突并默认停止，不静默覆盖。

#### FR-16-09 保留策略

按每项目最大数量、总空间和时间清理旧快照。清理当前项目快照需二次确认，并记录结果。

## 5. 非目标

- 不把轻量语法诊断宣传为完整语言服务器能力。
- 不替代正常 Git commit、branch 和 remote 流程。
- 不恢复项目根之外文件。
- 不在未预览的情况下自动恢复。
- 不保证任意二进制和超大文件快照。

## 6. 异常与边界场景

- Language Server 崩溃时本次诊断降级，Agent 主流程继续。
- 文件已删除或重命名时诊断与快照按路径版本处理。
- 快照空间不足时停止新增快照并在下一次写入前警告。
- 恢复中断时利用保护快照和原子写入避免半恢复。
- 同一项目多个工作树必须使用不同快照空间。

## 7. 验收标准

1. Java 文件引入语法错误后，下一轮 Agent 能收到带位置的诊断。
2. 连续修改时旧版本迟到诊断不会覆盖新结果。
3. 快照操作不改变用户 `.git` 的 HEAD、分支和暂存区。
4. 一次代码任务可以恢复到修改前内容，并且恢复前有保护快照。
5. 检测到无法归属的用户改动时默认拒绝覆盖。
6. 诊断或快照服务失败不会导致 CLI 无法继续使用。

## 8. 测试与验证

- 诊断测试：语法错误、结果排序、防抖、超时和 Server 崩溃。
- 快照测试：新增、修改、删除、重命名、恢复和保留清理。
- Git 隔离测试：分支、索引和未提交改动前后完全一致。
- 故障注入：磁盘不足、写入中断和损坏快照。
- 手工演示：制造错误、自动诊断、恢复本轮修改。

## 9. GitHub 交付物

- 诊断数据流和支持语言矩阵。
- Side-History 存储边界说明。
- 恢复前后演示 GIF。
- 用户 Git 状态不受影响的自动测试。

## 10. 下一阶段接口

Phase 17 的后台任务同样在开始前创建快照，并通过事件 API 暴露诊断与恢复状态，但远程 API 不得默认允许恢复操作。
