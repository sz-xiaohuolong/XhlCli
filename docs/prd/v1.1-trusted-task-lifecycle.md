## 1. 目标与依据

先让用户能相信“恢复只影响当前项目”“任务由正确的工作区执行”“取消、超时确实停止执行”“压缩不会因故障丢掉原文”，再继续扩大自主执行能力。

范围依据是 [2026-10-16 审查报告](../engineering/xhlcli-claude-qoder-review-2026-10-16.md)第 7 节第一批，以及用户于 2026-10-16 提出的“按照上述报告规划第一批拓展内容，沉淀需求、方案设计、实施文档到 v1.1”的明确请求。[原始验证记录](../engineering/research-2026-10-16/verification.md)已复现 R01～R07。竞品机制仅作为设计参考，不引入其源码或新依赖。

2026-10-16 交付为规划文档及 Agent 工作约定。范围基线已确定；设计仍为拟议方案，数据迁移和兼容策略的具体决定见设计第 7 节。功能实现、运行验收与发布尚未开始。

## 2. 本批范围

| 工作包 | 对应问题 | 用户可见结果 |
|---|---|---|
| 安全快照恢复 | R01 | 链接、目录变化或异常树项不能让恢复写到工作区外 |
| 工作区任务与租约 | R02、R03 | 双项目、双实例不会串任务；打开实例不会重排健康任务 |
| 取消和实际停止 | R04、R05 | 取消贯穿模型和工具；超时后不出现迟到写入、成功事件或冲突执行 |
| 可靠会话压缩 | R06、R07 | `/compact` 整理会话；摘要失败、取消或不合格时保留原文 |
| 能力声明校准 | 报告第 3.5、6 节 | Runtime、浏览器、Reviewer 的描述与真实入口和证据一致 |

不纳入报告第二、三批：会话持久化运行时、Headless/SDK、新 Runtime 入口或实时 SSE、工具全文制品库、浏览器点击输入、具有源码工具的 Reviewer、Repo Wiki、Java 诊断、Hook。保留现有审批、安全管线、多 Provider 与工具名称。

## 3. 用户行为与验收

测试接缝（SEAM）是可以从外部观察的验证入口：临时工作区、真实 SQLite、多实例、可阻塞假模型、受控进程和事件收集器。测试不能只断言新增字段或内部方法被调用。

| 需求 | 验收编号 | 可观察行为与通过条件 | 测试接缝 |
|---|---|---|---|
| REQ-01 安全快照恢复（R01） | AC-01 | 普通文件修改、缺失文件重建、目标中不存在的已跟踪文件删除仍正确；宿主 `.git` 与排除项保持不变 | SEAM-01：临时工作区、真实 Side-Git、文件内容与 Git 状态 |
| REQ-01 | AC-02 | 目标路径、父目录或快照树项存在软链接/特殊类型时按已批准策略安全拒绝；硬链接恢复不得改动同 inode 的外部文件；路径替换竞态不造成越界写入或删除。预检查失败不修改工作区，运行中失败报告已执行范围与保护快照 | SEAM-01：外部哨兵文件、链接与可控制的路径替换屏障 |
| REQ-02 工作区隔离（R02） | AC-03 | A/B 两个工作区共用任务库时，领取、列表、详情、取消均限定当前工作区；A 提交的任务只能在 A 的工具、安全策略、记忆与快照上下文中运行；无效工作区拒绝执行，路径别名不制造重复身份 | SEAM-02：共享临时库、两个规范根目录与两个真实装配入口 |
| REQ-03 正确租约（R03） | AC-04 | 同工作区双实例对同一任务仅一个成功认领；第二实例启动不改变健康 RUNNING；续约、完成、失败与取消确认均核对 owner 和领取代次；旧 owner 的迟到更新不覆盖新状态 | SEAM-03：两个数据库连接、可控时钟、领取与提交屏障 |
| REQ-03 | AC-05 | 仅按设计评审通过的策略处理过期租约；旧库升级保留任务 ID、prompt、工作区与历史结果；迁移中断可恢复，未知新 Schema 拒绝启动，无法确认归属的遗留任务不自动执行；验证备份恢复路径 | SEAM-03：旧版 SQL 样本、迁移故障点、过期任务样本 |
| REQ-04 后台取消（R04） | AC-06 | 排队中或等待执行的任务取消后，模型请求数和工具调用数均为零；运行中同一取消上下文到达模型/工具；前台和后台及两个后台任务的历史、预算、取消互不污染 | SEAM-04：真实 Agent/manager 装配、阻塞假模型、调用计数 |
| REQ-04 | AC-07 | “取消请求已记录”可立即展示；只有受管理执行已结束并完成清理才显示 CANCELED。重复取消幂等；另一实例发起的取消也生效；取消与完成竞态只产生一个终态，迟到完成不覆盖取消 | SEAM-04：跨实例取消、清理屏障、状态/事件收集器 |
| REQ-05 工具超时与停止（R05） | AC-08 | 串行、单工具和并行批次超时均触发该工具的取消与实际清理；命令父进程及受管理子进程退出后才确认停止；停止确认后无迟到文件写入或成功事件；同资源后续工具在清理完成前不能启动 | SEAM-05：真实工具/统一执行器、文件放行、父子进程与互斥探针 |
| REQ-05 | AC-09 | 单工具超时不取消同批独立的兄弟工具；排队时已超时的调用不启动；父 Run 取消级联全部子调用；不能确认停止时明确报告清理未完成并阻止继续执行相关冲突工作，不伪装正常完成 | SEAM-05：两个可控工具、调度器、资源占用和事件序列 |
| REQ-06 手动压缩（R06） | AC-10 | `/compact` 通过真实 Agent 压缩入口生成摘要并保留近期完整回合；目标、约束、已完成/未完成项、修改和验证信息在确定性样本中保留；小历史可明确返回无需压缩；`/clear` 继续负责清空 | SEAM-06：ChatLoop→真实 Agent、可预测摘要模型、历史快照 |
| REQ-07 自动压缩（R07） | AC-11 | 摘要成功且候选有效才替换；模型异常、错误、空白、工具调用响应、缺字段、超时、取消、预算不足或历史版本变化时原历史及工具配对不变；失败原因不冒充摘要 | SEAM-07：结构化假响应、失败/取消/模型切换与提交屏障 |
| REQ-07 | AC-12 | 摘要请求服从所属 Run 的取消与剩余时间；成功候选重新装配上下文并复核预算后再请求模型；仍超预算时保留历史并给出明确失败，不发送已知超出本地估算限额的请求 | SEAM-07：请求捕获、现有 TokenBudget、可控截止时间 |
| REQ-08 能力声明校准 | AC-13 | README、当前文档、官网和帮助中 Runtime/浏览器/Reviewer 的声明都有生产入口或组件测试证据及限制；计划能力明确标记，不据历史金标断言修复完成 | SEAM-08：声明→源码入口→验证证据矩阵与静态文案核对 |

## 4. 通用约束与兼容性

- 保持 Java 21、Maven 与现有统一工具安全管线：参数校验→硬策略→审批→执行→脱敏审计。用户批准不能绕过硬拒绝；修复不得增加后台默认权限。
- 沿用 `/task add/list/log/cancel`、`/snapshot`、`/restore`、`/compact`、`/clear`。取消的展示必须表达请求与确认的区别；具体字段兼容方案见设计。
- 后台无人值守时，需交互审批的操作保留现有安全默认行为，不能复用前台已批准的任意权限或争抢终端输入。
- 任务库路径覆盖配置继续有效。保留历史记录，不静默删除、跨工作区迁移或执行未确定归属的旧任务。具体 Schema、恢复语义与回退在实施前评审。
- 快照保留 Pre-Restore 保护及排除规则；不承诺多文件恢复是文件系统事务。取消/超时不撤销此前已经完成的修改，也不承诺能停止远端服务已经受理的请求。
- 摘要是有损压缩，不能承诺自然语言事实百分之百无损；通过结构校验、关键约束样本、完整工具回合和失败保原文验收。Token 数采用现有本地估算，不宣称与 Provider 计数精确相同。
- 并发测试使用闩锁、可控时钟和条件屏障；全部核心回归可离线运行，不依赖真实 Key、网络、用户主目录或全局 Git 配置。

## 5. 发布成功条件

AC-01～AC-13 全部有适用于最终代码的通过证据；原 7 个失败场景进入常规回归套件；迁移与恢复演练完成；能力声明校准完成；受影响及全量回归通过。版本更新和发布另按明确授权执行，本轮不修改 `pom.xml` 或创建 Tag。
