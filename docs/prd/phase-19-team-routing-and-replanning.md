# Phase 19：Team 自动选择与失败重规划

需求状态：`FROZEN`。确认依据：用户于 2026-11-06 确认自动进入现有 Team、失败驱动重规划及默认阈值，并授权文档、实现、测试、提交与远程同步。

## 1. 背景与目标

当前终端只有 `/team` 显式进入团队协作；Team 内审查失败只能重试原步骤。本次让普通输入可自动选择 Team，并在原计划走不通时重新安排剩余工作。面向使用终端开发项目的用户。

## 2. 范围

保留现有编排器、规划者、执行者、审查者流程；新增自动选择开关、步骤失败评估、最多两次重规划、成果保留及状态提示。继续沿用统一工具权限与审批。

本次不实现自由创建子 Agent、网页聊天、会话数据库、完整聊天重启恢复或 v1.1 的全部可信任务生命周期修复。应用版本仍由 pom.xml 决定，本次同步代码不包含打 Tag 或发布版本。

## 3. 用户场景

用户可以直接描述跨模块需求，由模型选择执行模式；也可以 `/team <目标>` 明确指定。局部错误先修正，任务拆解错误再换计划。取消、网络或权限问题不能被当成换方案的授权。

## 5. 行为与验收

### 自动选择

默认 `manual` 保持原行为；`--team-mode auto`、环境变量 `XHLCLI_TEAM_MODE=auto` 或全局配置 `teamMode` 开启，优先级沿用现有配置规则。会话内 `/team-mode auto|manual` 切换，`/team-mode` 查询；会话切换不写全局配置。显式 `/team` 始终直接执行。每个普通回合只选择一次，分类请求无工具权限；无效响应或请求失败回退普通模式，用户取消则结束本轮。自动选择会增加一次模型请求。

### 重规划

单步最多两次修正重试，耗尽后评估；执行异常、取消、工具拒绝和审查服务异常不进入换计划路径。模型必须明确确认计划问题，返回原因与新任务图。DAG 指无环的任务依赖图，决定哪些步骤必须先做。

当前计划已完成步骤数除以总步骤数低于 50% 时，可调整全部剩余工作；达到或超过 50% 时，只调整失败步骤及其下游依赖。一次用户任务最多两次重规划，次数不会因换图而重置。新计划无效或模型判断不宜重规划时保留失败结果。已完成步骤保留且不能重新定义、执行。

| 验收 | 给定、操作与预期 | 检查入口 |
|---|---|---|
| AC-19-01 | manual 下普通输入走原 Agent；显式 /team 绕过分类 | ChatLoop 集成测试 |
| AC-19-02 | auto 下模型分别选择普通与团队，输入恰好执行一次；关闭后不分类 | ChatLoop、配置测试 |
| AC-19-03 | 分类格式错误或网络失败回退；分类时取消不启动任何执行器 | 路由与取消测试 |
| AC-19-04 | 早期步骤重试耗尽、模型确认计划问题后换图；已完成成果不重复执行 | Team 集成测试 |
| AC-19-05 | 后半程只允许调整失败分支；其他待办与完成项保持不变 | Team 重规划测试 |
| AC-19-06 | 全轮最多两次重规划；STOP、无效图、循环、重复 ID、未知依赖均不执行新图 | Team 重规划测试 |
| AC-19-07 | 取消、权限拒绝、网络异常不触发换计划；并行旧任务收拢后才切图 | 工具和并发测试 |
| AC-19-08 | 失败尝试的工具证据与工作区变化进入交接；不清理或回滚已有文件 | 临时工作区测试 |
| AC-19-09 | 自动/手动 Team 获得当前上下文，结果可供普通对话追问；清空会话生效 | ChatLoop 与真实 Agent 测试 |
| AC-19-10 | 帮助、配置、人工验收与实际入口一致；重启后仅恢复安全输入历史 | CLI 冒烟与文档检查 |

## 6. 交互

终端展示正在选择模式、进入 Team 的原因、重规划次数及原因、最终成果/失败。空输入无请求。分类失败可降级；新计划非法明确失败，不伪装完成。无网页刷新入口。

## 7. 限制

模型判断不保证每次相同。50% 是步骤计数比例，不代表工时。复用原权限与工具实现，未验证的 v1.1 修复不属于本次完成声明。重规划不撤销已产生的副作用，新的 Worker 必须先核对工作区。

## 8. 观测

只使用现有终端输出和工具审计，不新增遥测。输出重规划计数与原因，内部分类原始响应不直接打印。
