# Phase 11：多模型适配 PRD

> 优先级：P1
> 状态：已规划
> 前置阶段：Phase 01、05
> 对应里程碑：M3 开放生态与产品体验

## 1. 阶段目标

将模型能力从 Agent 核心中解耦，支持多个 Provider 的统一配置、流式文本、工具调用和能力声明，并允许用户在运行时安全切换模型。不同 Provider 的协议差异必须被封装在适配层内。

## 2. 用户价值

- 用户可以根据价格、速度、上下文和工具能力选择模型。
- 切换模型不需要重启或修改代码。
- 模型不支持图片、工具或长上下文时，产品能提前提示或安全降级。

## 3. 本期范围

- 稳定的 `LlmClient` 产品接口与 Provider Registry。
- 至少两个 Provider：一个 OpenAI-compatible、一个具有协议差异的实现。
- 流式文本、工具调用、Token 用量和错误映射。
- 模型能力声明：上下文窗口、工具、图片、Prompt Cache、Reasoning 续轮需求。
- `/model list`、`/model use`、`/model status`。
- 非敏感配置持久化与环境变量 Key。
- Provider 兼容性契约测试。

## 4. 功能需求

### FR-11-01 Provider 抽象

Agent 只依赖统一消息、流式事件、工具描述和完成结果，不出现具体 Provider 请求字段或错误码。

### FR-11-02 能力声明

每个模型声明上下文窗口、是否支持工具调用、图片输入、Prompt Cache 和特殊历史字段。调用前校验能力，不发送已知不兼容的请求。

### FR-11-03 模型切换

用户列出可配置模型并选择 Provider/模型。切换后重新计算上下文预算；若当前历史与新模型不兼容，提示压缩、降级或新建会话。

### FR-11-04 配置来源

Provider 配置支持 Base URL、模型名、API Key 环境变量、超时和必要自定义参数。状态命令展示配置是否完整但不展示凭据。

### FR-11-05 错误统一

鉴权、配额、限流、模型不存在、上下文超限、内容过滤、网络、服务端和协议错误映射为统一类型，并保留 Provider 可诊断信息。

### FR-11-06 工具调用兼容

同一组 Tool Schema 在不同 Provider 下通过契约测试。Provider 特殊字段、流式 Tool Call 拼接和历史续轮逻辑由适配器处理。

### FR-11-07 用量与成本

Provider 返回用量时记录输入、输出、缓存 Token；成本只在存在明确价格配置时估算，并标记估算时间和来源。

### FR-11-08 默认与回退

用户显式选择的模型失败时不得静默换到可能产生费用或数据流向不同的 Provider。可以建议替代，但需用户确认。

## 5. 非目标

- 不接入尽可能多的 Provider。
- 不自建统一模型代理服务。
- 不承诺不同模型生成完全一致的结果。
- 不在仓库中保存 API Key。
- 不自动根据任务切换付费 Provider。

## 6. 异常与边界场景

- 当前模型不支持工具时，Agent 模式拒绝启动并建议文本对话或切换模型。
- 切换到更小窗口模型时，在下一次请求前处理超预算历史。
- 流式工具参数分片不完整时不执行工具。
- Provider 返回未知角色或内容类型时安全拒绝并记录兼容性信息。
- 配置文件中的模型已下线时提供可诊断错误，不覆盖用户选择。

## 7. 验收标准

1. 两个 Provider 可以完成相同的流式文本和多步工具调用契约场景。
2. `/model use` 后新请求使用目标模型并更新上下文预算。
3. 不支持工具的模型不会进入工具执行循环。
4. Provider 特殊历史字段在需要时正确续传，不影响其他实现。
5. 错误分类和敏感信息脱敏在各 Provider 上一致。
6. 未经用户确认不会自动切换到其他 Provider。

## 8. 测试与验证

- 契约测试：文本流、工具流、错误、取消、用量和上下文超限。
- Mock Server：不同分片方式、未知事件和半截响应。
- 切换测试：大窗口到小窗口、工具模型到文本模型。
- 手工验证：两个真实 Provider 完成同一基准任务。
