# Phase 15：终端产品化 PRD

> 优先级：P1
> 状态：已规划
> 前置阶段：Phase 01–14
> 对应里程碑：M3 开放生态与产品体验

## 1. 阶段目标

把已有 Agent 能力整合为稳定、清晰、可降级的终端产品体验。用户可以在同一界面完成输入、查看流式回答、观察工具与计划状态、处理审批、引用路径和管理命令，同时终端渲染与 Agent 业务保持解耦。

## 2. 用户价值

- 用户能够快速理解当前模型、模式、上下文、任务进度和权限状态。
- 长输出、并行事件和审批不会破坏输入行或终端历史。
- 不支持复杂终端能力时仍能使用纯文本模式完成任务。

## 3. 交互形态

### 默认：行内流式终端

保留原生终端滚动历史，在底部提供输入和轻量状态区域。回答、工具、计划和差异按事件写入正文，不使用永久占满屏幕的多栏布局。

### 降级：Plain 模式

只使用标准文本行，不依赖 ANSI 光标控制、颜色、折叠或动态状态，适用于 CI、重定向和不兼容终端。

全屏 TUI 可作为后续实验，不属于本期完成条件。

## 4. 本期范围

- Renderer 接口与行内、Plain 两种实现。
- 启动首屏、输入提示、流式输出和底部状态。
- Markdown 的标题、列表、代码块、表格和链接基础渲染。
- 工具调用折叠、Git diff、计划和 Multi-Agent 状态。
- 审批交互与输入恢复。
- 斜杠命令补全、路径引用补全和实时高亮。
- 输入历史、敏感内容过滤和 `/history clear`。
- `/clear`、`/compact`、`/model`、`/mcp`、`/skill`、`/task` 等命令统一发现。
- `NO_COLOR`、窄终端和输出重定向降级。

## 5. 功能需求

### FR-15-01 首屏

首屏只展示产品名、版本、当前模型、项目目录、关键扩展状态和三条以内入门提示。外部服务详细日志不得淹没输入提示。

### FR-15-02 输入稳定性

流式输出、工具事件和后台状态更新不能覆盖当前输入。提交后用户原始输入应写入可见历史，并与下一轮输出区分。

### FR-15-03 状态区

状态区显示当前模式、运行阶段、模型、上下文占用、Token/耗时、MCP/Skill 摘要和工作目录。字段超宽时按优先级裁剪，不能换行破坏布局。

### FR-15-04 流式正文

回答内容增量渲染。模型输出、工具摘要、错误和系统提示具有可辨识但克制的视觉层级。关闭颜色后语义仍清楚。

### FR-15-05 工具与差异

短工具结果直接显示摘要，长结果默认折叠并可展开。文件变更显示文件名和增删行；完整 diff 可按需查看。

### FR-15-06 审批体验

审批期间暂停普通输入，显示影响摘要和可用按键。决策完成后恢复原终端区域，不能遗留 raw mode 或破坏输入历史。

### FR-15-07 命令补全

统一补全斜杠命令、子命令、Provider、MCP Server、Skill 名称和项目内路径。补全候选来源与实际命令注册保持一致。

### FR-15-08 输入高亮

识别斜杠命令、`@path`、图片引用和明显敏感或危险片段。高亮仅为视觉提示，不修改最终提交文本，也不替代权限策略。

### FR-15-09 输入历史

历史默认持久化在用户目录，忽略空白、连续重复、疑似密钥、超长文本和图片 Base64。用户可以清空本地历史。

### FR-15-10 降级

检测到非交互终端、输出重定向或显式 Plain 模式时，不输出光标控制序列。`NO_COLOR` 禁止颜色但保留文本布局。

### FR-15-11 事件串行化

Agent、Planner、Worker、MCP 和后台任务不得直接竞争 stdout；所有用户可见输出通过 Renderer 或统一事件通道。

## 6. 非目标

- 不追求 IDE 级代码编辑器和文件树。
- 不依赖终端图片协议展示图片。
- 不把模型私有思维过程作为默认 UI 内容。
- 不用视觉高亮替代安全检查。
- 不要求所有终端具备完全一致的颜色和字宽表现。

## 7. 异常与边界场景

- CJK、Emoji、ANSI 和窄终端组合下按显示宽度裁剪。
- 审批、Ctrl+C、终端 resize 和后台输出同时发生时保持输入可恢复。
- Markdown 表格过宽时按列预算换行或降级为列表。
- 历史文件是目录、损坏或不可写时使用内存历史并告警。
- MCP 启动较慢时首屏按预算显示摘要，详细状态由命令查看。

## 8. 验收标准

1. 流式回答和后台事件出现时，正在编辑的输入不丢失、不被覆盖。
2. 审批完成或取消后终端模式和输入提示正常恢复。
3. 80、120、160 列终端下状态区和 Markdown 表格可读。
4. Plain 和 `NO_COLOR` 模式不包含不应出现的 ANSI 序列。
5. 输入历史不保存测试密钥、Base64 图片和超长输入。
6. 所有主要命令都能从统一补全入口发现。
7. Agent 三种执行模式均通过同一 Renderer 展示真实会话。

## 9. 测试与验证

- 虚拟终端测试：输入、resize、Ctrl+C、审批和异步输出。
- Snapshot Test：首屏、状态栏、工具块、diff 和 Markdown。
- 字宽测试：中文、Emoji、ANSI 和窄窗口。
- Plain 输出测试：无控制字符。
- 手工矩阵：macOS Terminal、iTerm2、Linux 终端、PowerShell/WSL。
