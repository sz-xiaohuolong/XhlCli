# Phase 05：上下文与记忆 PRD

> 优先级：P0
> 状态：已规划
> 前置阶段：Phase 02–04
> 对应里程碑：M1 可用 Coding Agent

## 1. 阶段目标

建立可预算、可压缩、可审计的上下文与记忆体系，让 Agent 在多轮和长任务中保留真正重要的信息，同时避免把全部历史、工具输出和项目文件无限累积到模型输入中。

## 2. 用户价值

- 长任务接近上下文上限时可以继续工作，而不是突然失败或遗忘目标。
- 项目稳定规则可自动加载，个人长期事实可由用户明确保存并跨会话复用。
- 用户能够查看模型当前使用的上下文类型，并删除不希望保留的记忆。

## 3. 记忆分层

| 层级 | 内容 | 生命周期 | 写入方式 |
|---|---|---|---|
| 运行状态 | 当前目标、计划、未完成项、工具边界 | 单次 Run | 系统自动维护 |
| 会话历史 | 当前会话 user/assistant/tool 消息 | 当前会话 | 对话自动产生 |
| 项目规则 | 构建命令、目录、约定、禁区 | 项目长期 | 项目文档显式维护 |
| 长期记忆 | 用户明确要求保存的稳定事实 | 跨会话 | 用户显式保存 |
| 检索上下文 | 与当前任务相关的记忆或代码片段 | 单次请求 | 按需检索 |

不同层级不能混写。当前任务中的临时结论不得未经确认自动升级为长期记忆。

## 4. 本期范围

- 模型能力与 Token 上下文窗口声明。
- 请求前预算估算、保留输出空间和工具结果空间。
- 工具结果按类型裁剪与摘要。
- 会话历史自动压缩和手动 `/compact`。
- `/clear`、`/context`、`/save`、`/memory list/search/delete/clear`。
- 项目规则文档的启动加载与大小预算。
- 项目级和全局长期记忆作用域。
- 压缩摘要的结构化最低保留项。

## 5. 功能需求

### FR-05-01 上下文预算

每个 Provider 声明上下文窗口。请求预算必须预留模型输出、下一轮工具结果和安全缓冲，不得用满官方窗口后再尝试压缩。

### FR-05-02 请求组装顺序

上下文按稳定顺序组装：基础系统规则、运行时信息、项目规则、按需 Skill 或记忆、会话历史、当前用户输入。每层有独立字符或 Token 上限。

### FR-05-03 工具结果治理

文件、搜索、命令和网络结果采用不同裁剪策略。工具结果被裁剪时保留来源、范围、错误和继续读取提示。

### FR-05-04 自动压缩

达到模型相关阈值时，压缩较早会话，但保留最近完整交互和 tool call/tool result 配对。压缩失败时采取更保守裁剪并明确告警。

### FR-05-05 压缩内容

摘要至少包含：用户目标、已完成事项、修改文件、关键决策、验证结果、未完成事项、失败原因、下一步和不可违反的约束。

### FR-05-06 手动控制

- `/context` 展示窗口、当前估算、各层占用和压缩状态。
- `/compact` 立即压缩当前会话。
- `/clear` 清空会话和临时检索上下文，但保留项目规则与长期记忆。

### FR-05-07 项目规则

启动时可以加载仓库内约定的项目规则文件。导入其他文件时必须限制在项目根内，并受总字符预算控制。

### FR-05-08 长期记忆

只有 `/save` 或用户明确表达“记住”时保存。记忆包含 ID、内容、作用域、创建时间和来源，不保存 API Key、临时日志或大段代码。

### FR-05-09 记忆检索与管理

长期记忆按当前任务关键词和作用域检索。用户可以列出、搜索、删除单条或清空作用域内记忆，删除立即生效。

### FR-05-10 可观察性

产品展示估算占用、是否发生压缩和注入了多少条记忆，但不默认打印记忆正文和完整系统 Prompt。

## 6. 非目标

- 不自动从对话中抽取用户画像或长期事实。
- 不把 RAG 代码索引当作长期记忆。
- 不承诺 Token 估算与 Provider 计费完全一致。
- 不将私密记忆同步到云端。
- 不用一个无边界摘要替换全部原始会话。

## 7. 异常与边界场景

- 项目规则超限时按文件优先级截断，并提示被忽略内容。
- 压缩请求失败时保留未压缩历史，不能丢失当前会话。
- 长期记忆文件损坏时隔离损坏记录并允许导出或重建。
- 当前模型切换导致窗口变小时，在下一次请求前重新预算。
- tool call 与 tool result 不能因裁剪被拆开，否则应同时删除或转为摘要。

## 8. 验收标准

1. 使用小上下文 Fake Model 可以稳定触发自动压缩并继续完成任务。
2. 压缩后用户目标、关键约束、修改文件和未完成事项仍可被后续请求读取。
3. `/clear` 不删除项目规则和长期记忆，`/memory clear` 不清除当前会话。
4. 未经用户明确要求不会新增长期记忆。
5. 记忆删除后下一轮检索不再返回该记录。
6. 上下文中不存在孤立的 tool call 或 tool result。

## 9. 测试与验证

- 单元测试：预算计算、分层顺序、工具裁剪、作用域和删除。
- 场景测试：自动压缩、手动压缩、切换小窗口、摘要失败和损坏存储。
- Golden Test：固定长对话压缩后必须包含结构化关键项。
- 手工演示：保存项目偏好、重启、检索、删除并确认不再注入。

## 10. GitHub 交付物

- 上下文分层图和预算说明。
- 压缩前后脱敏示例。
- 长上下文确定性测试集。
- 文档明确区分项目规则、长期记忆和会话摘要。
