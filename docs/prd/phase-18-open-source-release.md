# Phase 18：开源发行与评测 PRD

> 优先级：P2
> 状态：已规划
> 前置阶段：Phase 00–17
> 对应里程碑：M4 工程化发行

## 1. 阶段目标

把 XhlCLI 从可运行工程提升为可安装、可验证、可贡献的开源产品。建立公开基准任务、跨平台发行、文档网站级信息结构、版本治理和真实演示资产，使任何能力声明都能由代码、测试或可复现步骤支撑。

## 2. 用户价值

- 新用户可以用标准方式安装、升级、配置和卸载。
- 使用者能快速判断功能边界、支持平台、数据流向和已知风险。
- 贡献者有明确的 Issue、开发、测试、评审和发布流程。
- 项目能力可以通过公开任务集验证，而不是依赖主观演示。

## 3. 本期范围

- 语义化版本和自动发布流水线。
- macOS、Linux 和 Windows/WSL 的发行或明确支持策略。
- 可运行 JAR、校验和、SBOM 及 Release Notes。
- 安装、配置、快速开始、命令、架构、安全、扩展和排障文档。
- 基准任务集、评测运行器和结果报告。
- 端到端演示项目、终端录屏和架构图。
- CONTRIBUTING、CODE_OF_CONDUCT、安全披露和 Issue/PR 模板。
- 依赖、许可证、密钥和构建产物检查。

## 4. 能力声明规则

README 的“已支持”只包含满足以下任一证据的能力：

- 自动测试可重复验证；
- 公开基准任务有通过记录；
- 文档提供可复制的手工验证步骤和实际输出；
- 发行版本包含对应代码、配置和限制说明。

规划、实验和仅有接口占位的能力必须分别标记，不能与已交付混写。

## 5. 功能需求

### FR-18-01 安装与升级

至少提供直接下载可运行 JAR 的安装路径，并为常见平台提供脚本或包管理方案。安装流程验证 Java 21，升级保留用户配置并说明不兼容变化。

### FR-18-02 可复现构建

从干净检出使用文档命令产生与发布流程一致的产物。发布包含 SHA-256 校验和、版本信息和依赖清单。

### FR-18-03 发布门禁

发布前必须执行单元、集成、核心端到端、密钥扫描、依赖漏洞检查和文档链接检查。任一强制门禁失败不得发布正式版本。

### FR-18-04 基准任务集

任务至少覆盖：代码问答、精确定位、单文件修改、跨文件修改、失败诊断、安全拒绝、上下文压缩、计划执行、MCP 调用和恢复。每个任务包含初始仓库、用户 Prompt、期望性质、验证脚本和超时。

### FR-18-05 评测指标

记录任务完成率、验证通过率、工具错误、迭代次数、Token、耗时和高风险拒绝正确率。模型与环境信息随报告保存，结果不宣称跨模型绝对可比。

### FR-18-06 文档导航

README 面向首次使用；详细文档分别覆盖配置、命令、工作流、架构、Provider、MCP、Skill、安全、隐私、排障和贡献。内部实现说明不得挤占快速开始。

### FR-18-07 演示真实性

演示使用公开示例仓库或可发布的真实代码任务，保留完整输入、主要工具步骤和验证结果。剪辑不得隐藏失败后修正，也不得展示未发布能力。

### FR-18-08 开源治理

定义 Issue 标签、PR 检查项、代码评审要求、版本支持周期和安全漏洞私下报告渠道。贡献者可以在不接触真实 Key 的情况下运行测试。

### FR-18-09 供应链与许可证

记录直接依赖、许可证和来源；发布 SBOM。发现不兼容许可证或高危漏洞时阻止正式发布或明确采用修复版本。

### FR-18-10 迁移与兼容

配置、会话、记忆、索引、任务和快照格式变化必须有版本与迁移策略。无法迁移时先备份并给出明确重建步骤。

## 6. 非目标

- 不以 Star、下载量或页面美化替代产品质量。
- 不承诺所有操作系统和终端完全一致。
- 不为演示数据修改评测标准。
- 不发布真实 API Key、用户仓库或未脱敏日志。
- 不在本期增加新的主要 Agent 能力。

## 7. 异常与边界场景

- Release 构建与本地构建产物哈希不一致时中止发布并调查。
- 某平台未通过验证时在支持矩阵中标记实验性，不笼统写“跨平台支持”。
- 外部 Provider 不稳定导致评测失败时保留原始错误并区分产品失败与服务失败。
- 基准任务发生模型随机波动时多次运行并报告分布，不只选最好结果。
- 文档示例随命令变化时由链接和示例测试发现。

## 8. 验收标准

1. 新用户在受支持平台 10 分钟内完成安装、配置和首个任务。
2. 干净环境可以复现发布构建并校验产物。
3. 正式发布流水线的全部强制门禁通过。
4. 基准任务集至少覆盖十类核心场景，并能一键运行与生成报告。
5. README 的每项核心能力能映射到测试、基准或手工验收证据。
6. 发布物包含校验和、SBOM、Release Notes 和已知限制。
7. 贡献者无需真实模型 Key 即可运行主要单元与模拟集成测试。
8. 安全披露、许可证和隐私边界文档完整。

## 9. 测试与验证

- 安装矩阵：干净 macOS、Linux、Windows/WSL 环境。
- 发布演练：预发布版本完整生成、下载、校验、运行和升级。
- 文档测试：内部链接、命令片段和配置示例。
- 评测回归：固定模型配置与 Fake Model 确定性两套报告。
- 安全检查：密钥、依赖、许可证、SBOM 和产物内容。

## 10. GitHub 交付物

- 首个稳定版本 Release 与签名/校验信息。
- 产品首页 README、架构图和完整演示视频。
- 公开 Benchmark 目录与最新报告。
- Contributor Guide、Security Policy 和版本支持策略。
- Phase 00–18 能力—证据追踪表。

## 11. 长期演进入口

Phase 18 后的新需求先进入 Research 和总 PRD 变更评审，再创建独立子 PRD。候选方向可以包括更强语言服务、MCP OAuth、隔离执行环境和团队协作，但不得绕过现有安全、测试和证据门禁。
