# Phase 17：Runtime 与多模态 PRD

> 优先级：P2
> 状态：已规划
> 前置阶段：Phase 09、11、15、16
> 对应里程碑：M4 工程化发行

## 1. 阶段目标

扩展 XhlCLI 的任务入口和上下文类型：长任务可以进入持久后台队列并通过本地 Runtime API 查看事件；支持图片作为当前任务的补充上下文。两个子能力共享统一 Run、权限、事件、上下文和验证模型，不建立第二套 Agent。

## 2. 子阶段安排

- **Phase 17A：后台任务与 Runtime API**，必须先完成。
- **Phase 17B：图片上下文**，在 17A 稳定后交付。

17A 和 17B 分别验收与提交，任何一个未完成都不能将另一个表述为完整 Phase 17。

## 3. 子能力 A：后台任务

### 用户价值

- 用户可以把耗时任务加入队列，继续使用当前终端。
- 任务状态、日志和结果在进程重启后仍可查询。
- 本地工具或集成可以通过受保护 API 创建任务并消费事件。

### 本期范围

- 持久任务状态：`enqueued`、`running`、`waiting_for_approval`、`completed`、`failed`、`canceled`。
- 有界 Worker Pool、租约或恢复机制。
- `/task list/add/status/log/cancel`。
- localhost Runtime API：创建 Thread、提交 Turn、读取事件。
- API Key 鉴权、请求限流和事件游标。
- 后台模式的非交互审批策略。

### 功能需求

#### FR-17-01 持久队列

任务包含 ID、工作区、用户目标、创建时间、状态、尝试次数、截止时间和结果摘要。状态更新具备事务一致性。

#### FR-17-02 进程恢复

进程异常退出后，处于运行状态的任务根据租约判定为可重试或失败，不能永久卡在 `running`。

#### FR-17-03 工作区绑定

任务创建时固定规范化工作区，后续不能通过请求内容切换到其他目录。工作区不存在或权限变化时安全失败。

#### FR-17-04 非交互权限

后台任务无法弹出审批时，待批准操作进入 `waiting_for_approval` 或按精确预授权规则处理。不得自动进入 YOLO。

#### FR-17-05 Runtime API

服务默认只监听 loopback，启动必须配置 API Key。API 至少支持创建线程、提交任务和按游标读取事件，不直接暴露内部数据库。

#### FR-17-06 事件一致性

终端与 API 消费同一运行事件模型。事件带递增游标，客户端断线后可以从上次游标继续读取。

#### FR-17-07 取消

取消请求幂等；进入终态后再次取消返回现有状态。取消传播到模型、工具、MCP 和命令执行。

## 4. 子能力 B：图片上下文

### 用户价值

- 用户可以粘贴错误截图、界面稿或终端图片，让支持视觉的模型结合当前任务分析。
- 不支持图片的模型会明确降级，而不是发送非法请求。

### 本期范围

- `@image:<path>` 与剪贴板图片输入。
- 图片类型、大小、像素、来源和项目路径校验。
- 压缩、缩放、方向修正、透明背景处理和坐标映射元数据。
- Provider 图片能力判断与文本降级。
- 当前轮图片优先、历史图片 Payload 回收。
- MCP 图片结果进入统一内容模型。

### 功能需求

#### FR-17-08 图片引用

用户可以引用项目内或明确允许的本地图片。路径逃逸、未知格式、损坏文件和超限图片在发送前拒绝。

#### FR-17-09 预处理

按 Provider 限制压缩和缩放，保留原始尺寸与缩放比例。透明 PNG 使用确定背景处理，避免视觉模型误读。

#### FR-17-10 能力降级

支持图片的 Provider 接收标准图片内容；不支持时只发送来源和“图片未传递”的文本说明，并建议切换模型。不得把图片 Base64 错发到文本接口。

#### FR-17-11 历史治理

图片主要服务当前 Turn。进入后续 Run 时默认移除历史二进制 Payload，仅保留来源、尺寸和简短文字结论，控制上下文与成本。

#### FR-17-12 隐私提示

发送图片前用户能知道目标 Provider；共享浏览器截图和本地图片遵循相同凭据遮挡建议与审计规则。

## 5. 非目标

- Runtime API 不默认监听公网。
- 不实现多租户、云端任务编排和网页管理后台。
- 不支持视频、音频、OCR 专用流水线或图片生成。
- 不在终端内渲染高分辨率图片预览。
- 不允许后台任务绕过人工审批与硬策略。

## 6. 异常与边界场景

- 数据库损坏时停止 Worker 并提供备份与诊断，不新建覆盖旧库。
- 任务工作区被删除时进入失败并保留事件。
- API 客户端断线不取消任务，除非显式请求取消。
- 图片处理失败时不丢失用户文本部分。
- 图片包含疑似密钥时提示用户检查；产品不声称能可靠识别所有视觉敏感信息。
- Provider 在声明支持图片但返回拒绝时映射为能力或请求错误，不无限重试。

## 7. 验收标准

1. 后台任务在进程重启后可恢复为合理终态或重试状态。
2. Runtime API 未配置 Key 时拒绝启动，错误 Key 无法访问任务。
3. 事件客户端可断线后从游标继续，事件不重复改变任务状态。
4. 非交互高风险操作不会自动执行。
5. 支持视觉的模型能收到处理后的图片和尺寸元数据。
6. 文本模型不会收到图片 Payload，并给出明确切换建议。
7. 后续任务历史不重复携带旧图片二进制数据。

## 8. 测试与验证

- 队列测试：状态事务、重启恢复、租约、重试、取消和并发 Worker。
- API 测试：鉴权、限流、游标、非法工作区和请求大小。
- 图片测试：格式、方向、透明度、超限、损坏和路径围栏。
- Provider 契约测试：视觉支持与文本降级。
- 手工演示：后台代码任务与截图驱动的界面修改建议。
