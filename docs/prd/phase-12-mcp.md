# Phase 12：MCP 扩展体系 PRD

> 优先级：P1
> 状态：已规划
> 前置阶段：Phase 04、11
> 对应里程碑：M3 开放生态与产品体验

## 1. 阶段目标

集成 Model Context Protocol，使 XhlCLI 能以标准方式发现和调用外部 MCP Server 提供的工具与资源。MCP 能力进入现有工具、权限、审计、取消和上下文体系，不形成独立旁路。

## 2. 用户价值

- 用户可以通过配置接入浏览器、数据库、搜索或内部服务，而无需修改 Agent 核心。
- MCP 工具与内置工具拥有一致的调用、审批和错误体验。
- 外部资源可以按需引用，不必全部塞进系统 Prompt。

## 3. 本期范围

- MCP 客户端初始化与能力协商。
- stdio 与 Streamable HTTP 两种 Transport。
- 用户级和项目级 Server 配置合并。
- 工具发现、Schema 清洗、动态注册和调用。
- Resources 列出、读取与显式引用。
- Server 状态、日志、启停和手动重启。
- 列表变化和资源更新通知。
- 运行中取消及统一错误模型。
- Bearer 或自定义 Header 的环境变量注入。

## 4. 命名与配置

- 动态工具使用 `mcp__{server}__{tool}`，避免与内置工具冲突。
- 项目级同名 Server 覆盖用户级配置，并展示配置来源。
- `${VAR}` 仅从明确允许的环境和本地配置来源解析；解析失败时该 Server 不启动。

## 5. 功能需求

### FR-12-01 生命周期

Server 状态至少包含 `disabled`、`starting`、`ready`、`error`、`stopped`。单个 Server 失败不阻塞 CLI 和其他 Server。

### FR-12-02 启动预算

外部 Server 初始化有超时。CLI 首屏等待达到预算后允许用户进入交互，未完成 Server 在后台更新状态。

### FR-12-03 工具发现

成功初始化后读取工具列表，验证工具名和输入 Schema，并注册到统一 Tool Registry。Schema 包含不兼容结构时进行有记录的安全简化或跳过该工具。

### FR-12-04 动态调用

MCP Tool Call 使用原始 JSON 参数并返回文本、结构化内容或图片元数据。超时、取消、Server 错误和协议错误映射为统一 Observation。

### FR-12-05 权限与审计

所有 MCP 工具默认视为至少中风险，除非存在可信的只读元数据和本地策略。审批作用域可以绑定 Server，但敏感或写操作仍可要求单步批准。

### FR-12-06 Resources

用户可以列出和读取 Server Resources，并通过明确引用语法加入当前输入。默认只注入 URI 与描述索引，不自动读取全部正文。

### FR-12-07 状态命令

提供 Server 列表、状态、工具数量、错误摘要、日志、启用、禁用和重启入口。命令不打印环境变量中的凭据。

### FR-12-08 动态变化

收到工具列表或资源变化通知后刷新对应缓存。正在执行的调用继续使用其开始时版本，新调用使用更新后版本。

### FR-12-09 取消

用户取消 Run 时向支持取消的 MCP 调用发送取消请求，并忽略终态后的迟到结果。

### FR-12-10 配置安全

配置文件可以引用环境变量，但不得推荐明文 Key。HTTP Server URL、Header 和启动命令进入审计前脱敏。

## 6. 非目标

- 本期不实现 MCP OAuth、sampling 或 Server 崩溃自动退避重启。
- 不托管第三方 MCP Server。
- 不保证所有非标准 Schema 都能自动修复。
- 不允许 MCP Server 绕过路径、网络和审批策略。
- 不把所有 Resources 正文自动注入上下文。

## 7. 异常与边界场景

- Server 启动失败时保留日志摘要和手动重试入口。
- 同名工具发生变化时更新注册且不留下旧入口。
- Resource 正文超预算时按上下文规则截断并保留来源。
- stdio Server 向 stdout 输出非协议日志时隔离或报告协议污染。
- HTTP 连接重定向到不允许地址时由网络策略拒绝。
- MCP 图片结果在文本模型下转换为来源说明，不发送不兼容 Payload。

## 8. 验收标准

1. stdio 和 Streamable HTTP 示例 Server 均可发现并调用工具。
2. 单个 Server 超时或失败不阻塞 CLI 与其他 Server。
3. MCP 工具调用经过统一审批和脱敏审计。
4. 用户可以列出、读取并在当前任务中引用 Resource。
5. 工具列表变化后注册表正确更新。
6. Run 取消后不采纳迟到的 MCP 结果。
7. 配置和日志不暴露测试凭据。

## 9. 测试与验证

- 协议测试：initialize、tools/list、tools/call、resources/list/read 和通知。
- Transport 测试：正常、超时、异常退出、非法帧和取消。
- 生命周期测试：部分 Server 失败、禁用、重启和动态列表。
- 手工演示：接入一个文件外的只读 MCP 工具和 Resource。
