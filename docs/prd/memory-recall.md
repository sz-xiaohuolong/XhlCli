# 主对话长期记忆按需召回

需求状态：FROZEN。确认依据：用户于 2026-11-06 明确要求完成本文范围的文档、实现、测试及远程同步。方案见[设计](../specs/2026-11-06-memory-recall.md)，执行见[计划](../plans/2026-11-06-memory-recall.md)，结果见[验收](../engineering/memory-recall-verification.md)。

## 1. 背景

本次改动前，主 ReactAgent 把全局及项目记忆全量注入每次请求，且未将实际系统提示词、工具与记忆统一计入预算。目标是给模型足够的相关历史资料，减少无关内容占用；先优化发送给模型的内容，允许继续逐轮全量读取小规模 JSONL。

## 2. 目标与范围

本次只接入前台主 ReactAgent。保留 JSONL，不添加向量库、模型重排或额外 LLM 调用，不实现 search_memory 工具。Plan、Team、后台独立 Agent 保留原路径，不宣称支持新召回。无数据迁移，不自动推断过期、替代关系或矛盾事实。

## 3. 用户与场景

终端用户询问“当初为什么没有采用 Redis”，程序在模型开始前从绑定的全局/当前项目记忆中选出相关决策。后续“刚才那个方案呢”可补充最近两条用户消息；换话题时不带入无关历史。用户可预览匹配及查看上一轮实际注入情况。

## 4. 需求

| 编号 | 本次必需行为 |
|---|---|
| REQ-M01 | 从可信绑定目录读取，兼容旧记录，过滤无效生命周期与损坏记录 |
| REQ-M02 | 文本匹配、可解释排序、去重，允许零召回 |
| REQ-M03 | 每轮一次、同轮复用、下一轮刷新，不向持久对话历史追加动态记忆 |
| REQ-M04 | 条数与真实请求估算预算双重约束，保留当前问题和规则 |
| REQ-M05 | 只读诊断与约 30 题标注评测，清楚标明覆盖范围 |

## 5. 行为与验收

顺序：绑定目录读取 → 硬过滤 → 相关性排序 → 去重 → 条数/Token 选择 → 请求临时注入。记忆是历史参考资料，含来源及时间，不构成当前事实或执行授权。

- 可选字段 pinned 默认 false，expiresAt 默认不过期，supersededBy 默认无替代。过期和被替代的 pinned 同样排除。
- 初始上限 5 条、1500 估算 Token，最低分可配置；为约束少量 pinned，固定记忆也计入总条数和总预算，优先于普通条目。初始参数不声称最优。
- 英文大小写归一，技术标识符、文件名和错误码保留；中文使用二/三字片段，过滤常见功能词。词频不重复加分，按查询词覆盖和逆文档频率排序。不保证同义召回。
- 超长记录优先选择命中位置所在完整段落并标节选；无完整段落可容纳时跳过，不截断开头。
- 读取失败时本轮动态记忆为空；单条损坏只跳过该条并留安全诊断，不回退全量注入。
- 本轮内工具结果增长时，只能从本轮已选内容继续裁减，不重新读取/扩展。无记忆时请求仍超限，则明确停止该轮，不删除当前问题或关键规则，也不为召回追加摘要模型调用。

| 验收 | 给定—操作—可观察结果 | 检查入口 |

## 6. 交互

沿用 `/save`、`/memory list`；新增只读 `/memory recall <问题>` 预览匹配、分数、命中项和诊断。`/context` 展示主 ReactAgent 最近一轮实际注入的条目和预算；首次无结果、零召回与故障明确区分。管理 pinned/有效期/替代字段暂通过 JSONL 编辑，不新增一组写命令。

## 7. 边界

查询不接收任意存储路径，不跨项目搜索。诊断不记录记忆正文、凭据或底层异常原文。Token 继续采用项目估算器，结果是估算边界而非供应商精确 tokenizer。没有基础上下文空间时牺牲记忆而非用户输入。

## 8. 评测

使用约 30 个具备预期 ID 的人工可复核问题，比较全量注入和新召回的 recall、无关条数、估算 Token。用户确认没有现成真实问题数据，已授权自行设计：采用项目代表性场景，明确标为人工编写的样例，不冒称真实线上数据。真实模型答案是否漏掉关键约束由人工验收核实，离线测试不能替代。
