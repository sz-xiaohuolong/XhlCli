# Phase 08：Plan-and-Execute 智能规划系统评测报告

## 1. 评测目标与概述

本报告对 Phase 08 交付的显式 **Plan-and-Execute** 架构进行系统性验证与评测，重点覆盖：
1. 计划生成与拓扑排序（DAG 依赖合法性与环检测）。
2. 人机审阅交互（HITL Review：回车执行、取消零污染、补充约束重规划）。
3. 拓扑分层并发调度与日志缓冲隔离。
4. 失败处理、自适应重规划与熔断保护。
5. CLI `/plan` 命令与现有 ReAct 模式的无缝协作。

## 3. 核心能力与关键特性验证

### 3.1 严格有向无环图（DAG）与环检测
- **拓扑排序**：采用 DFS 三色标记法（白色未访问、灰色递归栈中、黑色已完成排序）。
- **环检测验证**：当检测到任务相互前向/反向引用（例如 `task_1` 依赖 `task_2`，且 `task_2` 依赖 `task_1`）时，`computeExecutionOrder()` 立即返回 `false`，并在 `Planner` 中抛出带有明确提示的异常，坚决阻止非法计划进入执行层。

### 3.2 简单任务智能短路
- **耗时与 Token 优化**：针对单步轻量任务（如“查看当前目录文件”），`Planner.isSimpleGoal` 自动命中短路规则，无需发起 LLM 网络请求即可在 1ms 内生成最小单步计划，大幅提升终端响应速度并节约 API 成本。

### 3.3 人机审阅交互（HITL Review）
- **零破坏性保障**：在用户确认前，系统绝不执行任何写文件或修改系统状态的工具调用；
- **自适应重排**：用户输入补充反馈后，系统将历史计划与新约束合并重新规划，确保用户意图精准落地。

### 3.4 分层并发与日志隔离
- **执行模型**：按照依赖解除顺序分层剥离可执行任务集合；
- **并发输出缓冲**：单任务在主线程直接调度；多任务批次采用最多 4 线程受控并发，并为各任务配置独立内存输出流（`ByteArrayOutputStream`），执行完毕后整块顺序输出，彻底解决了多线程并发日志在终端交错混乱的顽疾。

### 3.5 失败重规划与死循环熔断
- **动态自愈**：在计划推进进度小于 50% 出现步骤失败时，自动提取原目标、失败错误信息以及已成功的步骤先验，调用 `planner.replan` 进行自适应调整；
- **熔断保护**：引入 `MAX_REPLAN_ATTEMPTS = 2` 阈值，杜绝极端不可恢复错误下的无限递归重排，保证系统运行可靠性。
