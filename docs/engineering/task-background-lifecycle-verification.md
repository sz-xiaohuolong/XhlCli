# task 后台任务：交付、验收与业务流程

日期：2026-11-06。范围依据：[实施计划](../plans/2026-11-06-task-background-lifecycle.md)。本次是独立的后台只读任务优化，未发布新版本，`pom.xml` 仍为 1.0.1；不代表整个 v1.1 已完成。当前进度由 [PROGRESS](../PROGRESS.md) 维护。

## 1. 用户现在能完成什么

在终端输入 `/task add <目标>` 后立即继续前台对话。后台可以独立读取项目文件、检索代码或网页，保存当前输出与最终结果；用户可查看状态、发出取消请求，退出重启后继续查看已保存结果。同一项目打开两个 CLI 实例时不会重复领取健康任务；其他工作区不能列出、查询或取消该任务。

本次实现了独立执行、工作区隔离、跨实例取消、真实退出确认和持久化恢复。没有增加网页入口或后台编辑功能，不执行 Shell、Git diff、浏览器操作或 MCP 工具，也不继承前台对话与审批。MCP 是连接外部工具服务的协议，本轮后台不开放它。搜索语义索引、审计和任务数据库仍可维护工具基础设施文件，“只读”指不向模型提供修改项目内容的能力。

CLI 是终端命令行程序。本轮的“刷新”是再次输入 `/task list` 或 `/task log <id>`；重启后也使用这两个命令。它不是网页聊天记录刷新，也不是退出终端后仍运行的常驻服务。

## 2. 人工验收

### 前置条件及启动

准备 JDK 21、可获取 Maven 依赖的构建环境；仓库自带 Maven Wrapper，无需单独安装 Maven。使用真实模型需要按 [README](../../README.md) 配置有效凭据。可用 Python 3 运行本地模拟模型验收，无需真实凭据或付费调用。

```bash
cd /Users/daiyifei/Documents/code/agent-cli/xhlcli-task-background
./mvnw verify
python3 scripts/task_acceptance_demo.py
java -jar target/xhlcli-1.0.1.jar --help
java -jar target/xhlcli-1.0.1.jar --team-mode manual
```

本机使用独立交付工作区 `xhlcli-task-background`，避免覆盖原 `xhlcli` 目录中其他任务的未提交修改；其他机器替换第一行为拉取本次提交后的仓库路径。`--team-mode manual` 使本次前台验收不触发自动团队选择，不影响 `/task`。工作区是启动时的当前目录。

默认数据库为 `~/.xhlcli/tasks/tasks.db`。若要独立验收库，可先设置 `export XHLCLI_TASK_DIR="$(mktemp -d)"`，后续重启及另一终端使用同一个绝对目录。后台并发数默认 2，可用 `XHLCLI_TASK_WORKERS` 或 `-Dxhlcli.task.workers=N` 设置，限定 1～16；它是每个 CLI 实例的上限，不是跨进程全局上限。

### 操作和预期

| 步骤 | 具体操作 | 预期结果 |
|---|---|---|
| 提交 | `/task add 阅读 README.md，说明项目启动方式与限制` | 立即显示 `task_...` ID 和日志查询入口，终端可继续输入 |
| 并行 | 再提交一项只读分析，然后输入普通问题 | 后台与前台独立执行，前台不等待后台整项完成；后台不接收前台聊天历史 |
| 刷新列表 | `/task list` | 仅当前工作区的任务，状态从 `enqueued` 变为 `running`，最终 `completed` 或 `failed` |
| 查询当前输出 | `/task log <上一步返回的ID>` | 显示目标、工作区、时间；模型输出达到流式脱敏缓冲后出现“当前输出（尚未完成）”，短文本可能等到本轮结束才显示 |
| 查看完成结果 | 等待完成通知后再次 `/task log <ID>` | 通知只包含 ID、状态及查询命令；完整答案在日志结果中 |
| 取消 | 对运行中的较长任务执行 `/task cancel <ID>`，反复 `/task log <ID>` | 先记录取消请求；`cancel_requested` 表示仍等待退出，`canceled` 才表示本地执行停止。执行很快时可直接观察到终态；已完成任务不会改成取消 |
| 重启读取 | `/exit`，在相同目录、相同任务库配置下再次启动，执行 `/task list` 和 `/task log <ID>` | 已完成结果仍在，不重新调用模型；退出时运行任务会被请求停止，异常中断遗留任务标为失败并说明结果不确定 |
| 工作区隔离 | 在另一目录用同一个 JAR 和任务库启动，查询、取消原 ID | 列表不包含原任务，查询和取消提示未找到 |
| 双实例 | 同一工作区打开第二个同版本 CLI，查询首个实例运行任务并取消 | 健康任务保持运行且不被重排；第二实例可发起取消 |

真实模型耗时不固定。确定性验收使用 `python3 scripts/task_acceptance_demo.py`：它主动阻塞两项本地模拟请求，验证前台可用、流式输出、取消、重启和跨工作区查询。进程崩溃恢复由 `DurableTaskProcessTest` 通过独立 JVM（Java 运行进程）启动及强制结束来验证；不需要结束用户真实任务进程。

## 3. 一次消息从发送到重新显示

1. **接收命令**：`ChatLoop` 把 `/task` 参数交给 `TaskCommandFormatter`。它校验子命令，调用 `DurableTaskManager.enqueue`，返回任务 ID；普通前台消息仍走原有会话。
2. **先保存再确认提交**：manager 将目标、工作区真实路径、创建时间和 `enqueued` 状态写入 SQLite。SQLite 是保存在本机文件中的关系数据库，本次用于跨重启保留任务记录。任务提交成功不代表已经开始模型调用。
3. **领取任务**：工作线程只查询自己的工作区。先取得该 ID 的操作系统文件锁，再用带状态条件的 SQL 更新为 `running`。文件锁表示本机仍有进程持有执行权；条件更新防止多个领取者或取消请求覆盖彼此状态。锁一直保留到执行和清理结束，不按时间猜测进程是否失联。
4. **装配独立执行环境**：`BackgroundTaskRunner` 在开始执行时取得当前 CLI 模型配置，创建新的 ReAct Agent、工具注册表、历史、预算、取消控制和规则/记忆快照。ReAct 是模型交替思考、调用工具、读取结果的循环。本次每项任务使用独立循环，避免后台复用前台 Agent 的同步锁和历史。
5. **请求模型与调用工具**：上下文包含任务目标、规则、只读工具定义及本任务历史。Token 是模型处理文本的计量单位；`BoundedClient` 在每轮请求前估算消息和工具所占预算，预留回答空间，超限时失败且不发额外摘要请求。`TaskToolExecutor` 限制只读操作，关联取消令牌（传递停止信号的对象），跟踪工具是否真实退出。文本搜索使用 Java 引擎，不启动 `rg` 子进程。
6. **边执行边保存**：模型文本事件由 runner 汇集、脱敏，并约每 250ms 保存当前输出，最多 65,536 字符。manager 不在模型执行期间持有数据库互斥锁，因此前台查询、其他领取和取消可以继续。该字段是当前文本快照，不是完整工具事件日志。
7. **取消与结束**：排队取消直接变为 `canceled`；运行取消先保存 `cancel_requested`，所属实例约每 100ms 检查并传递信号。工具真实退出后 runner 才返回结构化结果。模型失败、整体超时或迭代耗尽映射为 `failed`；取消与成功竞争时，已接受的取消不能被迟到答案覆盖。完成时保存最终回答、错误、结束时间和耗时，再发简短通知。
8. **重新显示**：再次 `/task list/log` 时从 SQLite 读取当前工作区记录并格式化。重启也读相同库，不依赖内存聊天历史。扫描到运行状态但无法找到活跃文件锁时，manager 将其标为 `failed`，保留已保存输出、说明结果不确定，不自动重放；仍持锁的健康任务保持原状态。

入口及职责对应：`cli/ChatBootstrap` 装配与通知；`cli/ChatLoop` 分发；`runtime/task/TaskCommandFormatter` 命令呈现；`DurableTaskManager` 持久化和生命周期；`TaskFileLock` 本机执行归属；`BackgroundTaskRunner` 独立模型循环；`TaskToolExecutor` 权限、超时和退出屏障；`TaskOutcome` 真实结果映射。

## 5. 适用边界与回退

- 文件锁方案仅支持同一台机器的本地文件系统。不得混用旧版/新版进程访问同库，运行期间不得删除 `tasks.db.locks` 中的锁文件。文件锁不是跨主机租约。
- 保留现有表结构及既有索引；没有新增 Schema（数据库结构）或执行用户数据迁移。缺列旧库拒绝初始化并提示独立任务目录；无法确认工作区归属的旧记录保留但不展示、不执行。
- 取消确认表示本地模型调用和工具方法已经返回；不会撤销已完成操作，不能保证远端服务撤回已受理请求。无法及时退出的方法会继续保持取消请求状态；关闭 CLI 最多等待工作线程两秒，不承诺进程退出后继续运行。
- 当前输出是限长文本快照；最终成功答案完整保存。本轮没有完整事件回放、重试/续跑、前台聊天恢复、后台写权限、跨机器调度或后台自动摘要。Token 预算是字符估算，不保证与供应商精确分词一致。
- 模拟模型验证执行机制，不证明真实模型的分析质量；跨进程文件锁实测仅代表本机平台。v1.1 的安全恢复、前台进程治理和压缩仍按原计划独立推进。
- 回退使用本次提交的逆向提交。回退前停止所有新版实例，检查未完成任务；不依赖旧版的孤儿自动重排行为，也不要在运行时删除数据库或锁目录。
