# v1.0.1 用户配置支持 API Key 技术设计

> 日期：2026-10-07  
> 状态：方案已确定 (Requirements Frozen)  
> 目标版本：`v1.0.1`  
> 关联需求：对齐 Claude Code 等主流 CLI，允许在 `~/.xhlcli/config.json` 中持久化配置 API Key

---

## 1. 目标与设计原则

### 1.1 背景
在 `v1.0.0` 之前，出于防御性凭据安全策略，XhlCLI 显式禁止在 `~/.xhlcli/config.json` 中配置任何包含 `apiKey` 等敏感字段的内容（`containsSecretField` 拦截并抛出异常），仅允许从系统环境变量或当前工作区 `.env` 读取。
然而，像 Claude Code 等主流智能终端 CLI 均允许工程师在全局用户配置 `config.json` 中配置 API Key，以便在任意目录启动 CLI 时无需反复配置 `.env` 或向 Shell 配置文件注入全局变量。

### 1.2 核心目标
1. **解除凭据拦截限制**：允许在用户级全局配置 `~/.xhlcli/config.json` 中配置 API Key。
2. **多格式与兼容性**：
   - 兼容顶层 `apiKey`（默认作为主模型 Provider / DeepSeek 的 API Key）；
   - 支持多 Provider 细分字段：`deepseekApiKey`、`openaiApiKey`、`anthropicApiKey`；
   - 支持 `providers` 嵌套映射对象：如 `providers.deepseek.apiKey`、`providers.openai.apiKey` 等；
   - 兼容蛇形命名（如 `api_key`、`deepseek_api_key`）。
3. **严格的优先级解析 (Precedence)**：
   确定性优先级阶梯：
   `进程环境变量 (ENVIRONMENT) > 项目根目录 .env (DOT_ENV) > 全局用户配置 ~/.xhlcli/config.json (USER_CONFIG)`
4. **多模型 Provider 生态打通**：
   在 `ChatBootstrap` 中组装 `providerRegistry` 时，将 `userConfig` 中声明的各 Provider 凭据（如 `OPENAI_API_KEY`、`ANTHROPIC_API_KEY`）作为基础层与 `.env`、`environment` 合并，使得全局配置一次即可在运行时直接切换模型 (`/model use ...`)。
5. **脱敏保护不妥协**：
   终端 `/config` 指令、状态栏与日志输出中，API Key 来源正确标记为 `USER_CONFIG`，明文 Key 保持严格脱敏，绝不暴露。

---

## 2. 详细技术实现方案

### 2.1 结构扩展：`UserConfig` 与 `ProviderConfig`

在 `ChatConfigLoader.java` 中：
```java
public record ProviderUserConfig(
        @JsonAlias({"api_key", "API_KEY"}) String apiKey,
        @JsonAlias({"base_url", "BASE_URL"}) String baseUrl,
        String model) {}

public record UserConfig(
        @JsonAlias({"api_key", "API_KEY"}) String apiKey,
        @JsonAlias({"deepseek_api_key", "DEEPSEEK_API_KEY"}) String deepseekApiKey,
        @JsonAlias({"openai_api_key", "OPENAI_API_KEY"}) String openaiApiKey,
        @JsonAlias({"anthropic_api_key", "ANTHROPIC_API_KEY", "claude_api_key", "claudeApiKey"}) String anthropicApiKey,
        Map<String, ProviderUserConfig> providers,
        String model,
        String baseUrl,
        Long connectTimeoutSeconds,
        Long readTimeoutSeconds,
        Long requestTimeoutSeconds,
        Long agentMaxIterations,
        Long agentTimeoutSeconds,
        String logLevel,
        Long maxConcurrency,
        Long toolTimeoutSeconds) {

    public String getEffectiveApiKey() {
        if (deepseekApiKey != null && !deepseekApiKey.isBlank()) {
            return deepseekApiKey.trim();
        }
        if (providers != null && providers.containsKey("deepseek") && providers.get("deepseek").apiKey() != null && !providers.get("deepseek").apiKey().isBlank()) {
            return providers.get("deepseek").apiKey().trim();
        }
        if (apiKey != null && !apiKey.isBlank()) {
            return apiKey.trim();
        }
        return null;
    }

    public Map<String, String> toEnvMap() {
        Map<String, String> map = new HashMap<>();
        String dsKey = getEffectiveApiKey();
        if (dsKey != null && !dsKey.isBlank()) {
            map.put("DEEPSEEK_API_KEY", dsKey);
        }
        String oaKey = (openaiApiKey != null && !openaiApiKey.isBlank()) ? openaiApiKey.trim() : null;
        if (oaKey == null && providers != null && providers.containsKey("openai")) {
            oaKey = providers.get("openai").apiKey();
        }
        if (oaKey != null && !oaKey.isBlank()) {
            map.put("OPENAI_API_KEY", oaKey.trim());
        }
        String anKey = (anthropicApiKey != null && !anthropicApiKey.isBlank()) ? anthropicApiKey.trim() : null;
        if (anKey == null && providers != null && providers.containsKey("anthropic")) {
            anKey = providers.get("anthropic").apiKey();
        }
        if (anKey != null && !anKey.isBlank()) {
            map.put("ANTHROPIC_API_KEY", anKey.trim());
        }
        return map;
    }
}
```

### 2.2 解除敏感凭据拦截

移除 `ChatConfigLoader.java` 中的 `containsSecretField` 校验方法，允许 `readUserConfig` 顺利解析包含 API Key 的合法 JSON。

### 2.3 API Key 解析优先级联动

在 `ChatConfigLoader.load(...)` 中：
```java
Resolved<String> apiKey = firstNonBlankOrMissing(
        resolved(environment.get("DEEPSEEK_API_KEY"), ConfigSource.ENVIRONMENT),
        resolved(dotEnv.get("DEEPSEEK_API_KEY"), ConfigSource.DOT_ENV),
        resolved(userConfig.getEffectiveApiKey(), ConfigSource.USER_CONFIG));
sources.put(ConfigKey.API_KEY, apiKey.source());
```

在 `ChatBootstrap.java` 中：
```java
Map<String, String> userEnv = Map.of();
try {
    userEnv = ChatConfigLoader.readUserEnv(userHome.resolve(".xhlcli").resolve("config.json"));
} catch (Exception ignored) {}

Map<String, String> mergedEnv = new HashMap<>(userEnv);
mergedEnv.putAll(dotEnv);
mergedEnv.putAll(environment);
com.xhlcli.llm.LlmProviderRegistry providerRegistry = new com.xhlcli.llm.LlmProviderRegistry(mergedEnv);
```
