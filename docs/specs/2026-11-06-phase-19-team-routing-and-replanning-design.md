# Phase 19：Team 自动选择与失败重规划设计

状态：`APPROVED`（用户已确认范围并授权实施；不表示已验证）。需求见 [PRD](../prd/phase-19-team-routing-and-replanning.md)。

## 1. 目标与现状

普通输入由 ChatLoop 调用 ReactAgent；显式 Team 使用 TeamOrchestrator。保留两者，增加 TeamRouter 决策入口。Team 的步骤级重试继续存在，增加批次结束后的计划修订。

## 2. 技术基线

已核验：Java 21（本机 Corretto 21.0.8）、Maven Wrapper 3.9.9、Jackson 2.22.2、JUnit 5.10.2，依据 pom.xml、java -version、./mvnw -v。不增加依赖、数据库或迁移。遵循根 AGENTS.md。修改边界为 cli/config/team、必要的 ReactAgent 历史交接、帮助及对应测试。

验证：./mvnw test；./mvnw package -DskipTests；java -jar target/xhlcli-1.0.1.jar --help。并发 API 依据 Java 21 Future 官方文档：get 等待计算完成；cancel 不等于底层副作用已停止，因此不以取消 Future 作为切换计划依据。

## 3. 流程与模块

ChatLoop 接收输入 → 手动命令直接 Team / 普通输入按开关分类 → 使用同一轮取消令牌与快照边界执行 → Team 批次执行及审查 → 必要时评估剩余计划 → 输出总结并交回普通对话上下文。

TeamRouter 只接收必要历史、项目位置与当前输入，无工具；返回 REACT/TEAM 与原因。分类失败回退 REACT，取消不降级执行。配置沿用 CLI > 环境 > .env > 全局配置 > 默认。

## 4. 核心契约

- 模式：manual/auto；默认 manual。会话命令只改变本次进程状态，启动配置可持久保存在已有 config.json。
- 重规划响应：decision 为 REPLAN 或 STOP，reason 非空，REPLAN 带 steps。steps 仅包含剩余任务，已完成 ID 只能作为依赖引用。
- 初始图与新图均校验唯一 ID、非空目标、依赖存在、无自依赖与环。无效图不执行。
- 已完成步骤由编排器保留，模型不能重定义。低于 50% 允许替换剩余图；达到 50% 后，失败分支之外的待办定义必须一致。
- 新图必须实质改变失败分支，不接受完全相同或仅重命名 ID 的失败任务反复提交；一次 Run 最多两次修订。
- 批次全部 Worker 返回后读取实际文件变化和执行记录，才调用 Planner；执行器中断或取消时不切图。
- 每次 Worker 的工具名、状态与结果形成有界证据，任一权限/执行/审查异常阻止整图自动换计划。当前工作区变化以只读证据附入，工具记录缺失、工作区证据不完整或累计交接超过 64000 字符时停止自动重规划；执行者自述单独限长，每次审查缺陷进入证据。
- 对话传递保留必要约束与最近回合；不把全部工具历史复制给每个角色。Team 总结回注普通 Agent，避免下一轮追问失去上下文。

## 5. 取舍

采用独立无工具的模式选择请求，接口明确、可离线测试；代价是 auto 每轮增加一次模型请求。暂不把 Team 做成任意递归工具，也不改写 /plan 的现有重规划。

## 6. 安全与状态

新计划不能提高工具权限，沿用实际执行器的审批和硬策略。新图仅在完全校验后替换内存中的剩余图；不自动 reset、删除或回滚文件。结果区分成功、失败、取消；审查失败记录不能成为成功证据。终端输入历史继续由 SafeHistory 保存，完整聊天与执行状态不跨进程恢复。验收发现旧 SafeHistory 在读取器绑定前加载会失败，且每次追加全量旧记录；本次将加载移至绑定后并只追加新记录，不修改文件格式。

## 7. 验证与恢复

AC 对应测试入口见实施计划。失败时保留差异与报告，可用 /team-mode manual 停用自动选择。代码恢复以 Git 提交为单位，不改变用户工作区成果。真实付费模型质量不由离线测试代替，验收记录明确覆盖范围。
